## 11. 常见坑（踩过的，别再踩）

> **速查级**：每条只留「现象 → 根因 → 结论 / 改哪里」。专项细节在各自文档里（PTY `docs/pty-research.md`、TUI `docs/cli-tui-plan.md`、托盘 `src-tauri/src/tray/`、Rust 引擎 `docs/rust-engine.md`）；本节被压掉的长篇叙述与实验记录见 git 历史（`git log -p docs/AGENTS.md`）。

**11.1 PowerShell 5.1 按本地代码页（GBK）读文件** —— 看含中文的源码会乱码：读加 `-Encoding UTF8`；写统一用 `write_file` / `edit_file`（UTF-8）。

**11.2 本机沙盒的已知限制（环境行为，不是代码 bug）** —— `vitest` / `vite build` / `jest` / `node-gyp` / `child_process.exec*` 因 `esbuild` 子进程 `spawn EPERM` 跑不了。根因：libuv 给 spawn 的 stdio 建的是**命名管道**（NPFS 内置 SD 无 restricting SID 写 ACE → 受限令牌第二遍检查 `ACCESS_DENIED`）；**匿名管道不受影响**（python `subprocess(capture_output=True)`、`cargo`→`rustc` 均正常）。
退路：`execute_command` / `execute_script` 传 `sandbox:"off"`（按「沙盒脱壳」权限授权，`readonly` 拒绝）；不想每次授权就配「设置 → 安全 → 忽略沙盒命令」（命中即自动无沙盒，见 §5.4）。临时关闭：`VIRLEN_SANDBOX=off|readonly|on`（由 **Virlen 进程**读取，命令里 `set` 无效）。另：`node_modules` 可能不完整，先 `pnpm install` 再判错。

**11.3 版本号分散在 7 个文件 / 10 处，靠手动同步** —— `package.json`、`src-tauri/Cargo.toml`、`virlen-core|virlen-cli/Cargo.toml`、`src-tauri/tauri.conf.json`（**打包与 MSIX 实际读它**）、`Cargo.lock` 的三个本包条目、README ×2。用 `pnpm update`（`scripts/update-version.mjs` 已覆盖全部，`--dry-run` 可预览）。

**11.4 README ×2 需同步维护**（`README.md` / `README-CN.md`）—— 改工具数量、测试目录（`src/tests/`）、技术栈版本时最容易漂移。

**11.5 前端工程四条** —— `vite.config.ts` 的 `optimizeDeps.exclude: ['monaco-editor']` **不可去掉**（否则 monaco 打成多份实例、注册表互相隔离）；Vite 端口固定 1420（`strictPort`），`tauri dev` 会因占用失败；`tsconfig.json` 是 `strict: true` 但 `strictNullChecks: false`、`noUnusedLocals/Parameters: false`（别名 `@/*` → `src/*`，Vitest 另配一份）；Run Snapshot 只存内存、刷新即失效，用户取消**不算错误**（要保留 partial 内容，见 `docs/rust-engine.md`）。

**11.7 Windows `execute_command` 走 ConPTY（伪控制台）** —— stdout / stderr **合并为一条 VT 流**，`uiData.pty = true`（前端用 xterm 渲染，非 PTY 才回落 `<pre>`）；完整背景见 `docs/pty-research.md`。
- 给模型看的文本必须过 `process_terminal_output`（完整吞掉 ECMA-48 转义序列，**Rust / TS 两侧必须同步**）；**不要再假设子进程 stdio 是管道**。
- 交互走 Tauri 命令 `pty_write` / `pty_resize` / `pty_key`（**不经引擎事件总线**）。两条红线：用户输入正文**不回灌**给模型；终端内确认的命令**仍走沙盒 + 同一条执行路径**。
- 缺口：常驻交互 shell（Step 3）未做；Unix PTY 未实现（`runner/pty.rs` 整体 Windows 门禁，见 §11.31）。

**11.8 拖拽取文件路径：`dragDropEnabled` 只能为 `true`（与 HTML5 拖拽互斥）** —— 原生拖放能拿真实路径（`onDragDropEvent().payload.paths`），但页面收不到 HTML5 `drop`。实现：监听只有一份（`ui/hooks/useNativeFileDrop.ts`，宿主 `chat-view` 挂），各处只登记命中范围（输入框 `input/use-native-drag-drop.ts` / 右侧栏 `side-panel/index.tsx`，两处不要各自 `listen`，见 §11.54 ⑯）；同类手法散见于 `use-tree-drag.ts` / `sandbox-rules-dnd.ts` 的文件头。
附件：`MessageContent` 的 `file` 块**只存路径**，各 Provider 统一降级为文本（TS `fileBlockToText` ↔ Rust `provider.rs`，**两侧文案必须一致**；`ATTACHED_FILE_LABEL` / `ATTACHED_DIR_LABEL` 用英文、不进 i18n）。

**11.9 粘贴文件：路径只能问原生剪贴板**（页面 `DataTransfer` 里没有）—— `read_clipboard_file_paths`（`src-tauri/src/clipboard_files.rs` = `CF_HDROP`）；读不到一律返回 `[]`，**不报错、不打断粘贴**。前端在 `input/index.tsx` 汇到 `acceptPaths`，含 Ctrl+V 原生兜底（WebView2 对「复制的文件」可能连 `paste` 事件都不触发）。

**11.10 输入框高度模型：固定高度只落在 textarea 上**（否则附件把工具条顶出盒子）—— 两个必须对齐的常量：`index.tsx` 的 `INPUT_CHROME_HEIGHT = 58` ↔ `style.scss` 的 `.input-wrapper` 静止高度 125 / `textarea { min-height: 67px }`；`.has-fixed-height textarea` 必须 `flex: 0 0 auto`。

**11.11 Windows 上 `cargo test` 可能连启动都启动不了（comctl32 v6 清单）** —— 报 `0xc0000139` 且无任何 Rust 输出，而 `cargo build` / `check` 正常。根因：托盘**菜单**（muda）链进 comctl32 **v6 专属**导出 `TaskDialogIndirect`，而带 RT_MANIFEST 的 `resource.lib` 只经 `rustc-link-arg-bins` 给了 **bin** → 测试二进制在**加载阶段**就失败。修法在 `src-tauri/build.rs`：全局 `/MANIFEST:EMBED` + `/MANIFESTINPUT:windows/common-controls.manifest`，同时给 bin 加 `/MANIFEST:NO`（否则 `CVT1100 duplicate resource`）。定位手法可复用：解析两个 exe 的 PE 导入表做差分。

**11.12 单实例：`tauri-plugin-single-instance` 必须第一个注册，且它自己会 `process::exit`**
- **顺序**：插件 `setup` 按注册顺序执行、都在 `App::build()` 内（`initialize_plugins`），**早于** `.setup()` 回调与窗口创建 → 不在链上第一个的话，第二实例会先建好窗口 / 托盘 / SQLite 再被杀。
- **清理**：第二实例的退出**绕过** `tray::destroy()`（不发 `NIM_DELETE` → 幽灵图标）。当前无事（那时还没建托盘），但**别**在 `tauri.conf.json` 加 `app.trayIcon` —— 那个默认托盘在 `initialize_plugins` **之前**就建好了。
- **dev 下不注册**：`lib.rs::run()` 用 `if !tauri::is_dev()` 包住，否则没关干净的 dev 实例（关窗只隐藏到托盘）会把新起的 `pnpm tauri dev` 顶掉，表现为「跑完什么都没出现」。判定信 `tauri::is_dev()`（= `DEP_TAURI_DEV`），**别**自己写 `cfg!(feature = "custom-protocol")`（本包没声明该 feature，恒 true = 永远算 dev）。
- 窗口唤起统一走 `tray::activate_main_window(app, reason)`（**不清未读**）。

**11.13 切会话有唯一入口 `chat-view.tsx::handleSelectSession()`** —— 外部只改 `chatState.currentSessionId` 会「跳过去但消息列表是空的」（它还要 SQLite 懒加载、`setMessages` 镜像、中断残留修复、用户消息索引、埋点、清红点）。
外部入口（托盘唤起等）拿不到组件函数 → `chat-view` 有「外部入口兜底 effect」（`handledSessionRef`）接住：**新增外部切会话入口只改 store**；组件内自己切（如 `doSend` 新建会话）必须登记 `handledSessionRef`，否则兜底 effect 会按旧内容覆盖刚加的消息。另：`message-list` 的 `hide`（`opacity: 0`）在 `messages` 为空时也必须解除（见 `use-scroll-controller.ts`）。

**11.54 右侧面板 = 容器（`side-panel`）+ 内容（`workspace-file` / 服务终端等），十九个不能踩的点** —— 标签页容器把「多个文件同时打开」变成了常态，随之而来的坑全在**生命周期**上：
- **① 切标签绝不能卸载内容**：文件面板的草稿只活在组件 state 里（没进 store、没进 SQLite），卸载即丢；Monaco 的撤销栈、滚动位置同理。所以所有标签的内容**一直挂着**，`<div hidden>` 只切显隐（`.side-panel-pane[hidden] { display: none }`），`CodeEditor` 的 `automaticLayout` 会在重新显示时自己补一次 layout。
- **② 每个标签的脏回调必须是稳定引用**：面板里的 `useEffect(() => onDirtyChange?.(dirty), [dirty, onDirtyChange])` 一旦拿到内联箭头，就变成「面板每渲染一次 → setState 一次」；容器用 `dirtyHandlersRef`（`Map<id, handler>`）缓存，标签关掉时连同脏状态一起删（不删的话宿主会一直被「有未保存草稿」拦住）。
- **③ 宽度 / 拖拽 / 占满归容器，不要下放给每个内容区**：旧实现把这些写在 `workspace-file` 里（自带 `<aside>`、`.wfp-resizer`、`measureAvailable`），多标签时就会「每个面板各拖各的」。现在 `side-panel/index.tsx` 独占这一套（`MIN_WIDTH` = 360 / `CHAT_MIN_WIDTH` = **450** / `preferredWidth` / `is-full`），内容区只负责自己那块；宽度按**聊天区（chat-main）的一半**算，且**绝不把聊天区压到 `CHAT_MIN_WIDTH`（450）以下** —— 窗口不够宽先缩面板，只有连「最小面板 + 450」都放不下才轮到 `is-full`；每次**打开**重算一次（容器常驻挂载，不在打开那一刻重算就会停在旧的一半），加标签 / 切标签不重算，用户拖过之后不再自动改回来（拖出来的宽度是用户的意思）。**拖宽不设固定上限**：`MAX_WIDTH`（960）与 CSS 的 `max-width: 72vw` 都已拿掉，`maxDragWidth()` 直接给到「聊天区 + 面板」的整块可用宽度（再宽没意义：到那之前已进入 `is-full`）。
- **④ 网页标签的导航是命令，地址靠两类事件回传**：只有地址栏回车才 `navigate`；后退 / 前进**只发原生历史命令**（`browser_view_history` → WebView2 的 `GoBack` / `GoForward`），面板不存历史条目，也**绝不因「地址变了」补一次导航**（两个根因与五条口径见 §11.57 ⑮）。回传分两条路：`on_page_load`（真实导航）与 Windows 的 WebView2 `SourceChanged`（**SPA 的 `history.pushState` 不触发页面加载，只有它会响**）。⚠️ 三条容易漏：**(a)** 进度条要有 15s 兜底 —— DNS 失败 / 证书错时可能永远等不到 `finished`，不能一直转；**(b)** 前端订阅时**回调必须存 ref**，不能进 `useEffect` 依赖数组 —— 宿主每次渲染传的都是新箭头函数，进依赖会让监听「卸载 → 异步重注册」，事件落在那个空档里就丢了（**现象的典型描述：网页能开，但地址栏完全不跟手**）；**(c)** 事件里带的是视图 label，多标签时必须按 label 过滤，否则两个网页标签会互相改地址。
- **⑤ 标签 id = 内容身份**（文件 `file:<绝对路径>`；服务终端 `service:<会话id>:<服务id>`，服务 id 只在会话内唯一）：同一个内容再点一次是「激活已有标签」，不是再开一个 —— 文件开两份会各持一份草稿互相踩，终端开两份则是两个 xterm 抢同一个伪控制台（键击与尺寸互相打断）。渲染分支在 `side-panel/index.tsx::renderTab(tab, active)`：`file` → `workspace-file`，`service` → `service/ServiceTerminal`（标签的会话 id 是**点开那一刻**固定的 —— 新对话页的全局视图里它可能属于另一个会话；切走时只传 `active=false` 停轮询，标签仍然挂着）。
  AI 的**交付物**（`present` 工具）走同一条路：`tool_result_created` 收 `uiData.type = "present"` → `services/present-service.ts` → 宿主的 `openFilesToBucket()` / `openBrowserToBucket()`（一次算完、激活第一个）。⚠️ **交付落在「跑出这次交付的那个会话」那一桶**（payload 必带 `sessionId`，宿主用 `panelKeyOf(sessionId)` 落桶）：用户当时可能正看着别的会话 / 新对话页（后台会话跑完），按「当前会话」一刀切 = 交付静悄悄丢了；落在别的桶**不会抢眼前的面板**（`withBucketTabs` 只展开目标那一桶），侧栏会话徽标会亮、切回去就是打开着的样子。别在事件处理器里自己算标签。交付物**默认落在「预览」**（`present` 的语义是给人看，不是给人改）：宿主的 present 入口传 `view: 'preview'` + 自增的 `viewSeq` + `pinned: true`，标签记在 `SidePanelTab.view/viewSeq/pinned` 上 → 面板的 `defaultView`；普通打开不带 view、仍是编辑，`viewSeq` 变化让「同一个文件再交付一次」能从编辑迁回预览（`path` 没变时 `load()` 不重启，只靠这个序号）。⚠️ 只有**能预览**的类型才认它（`textPreviewKindOf` 为 null 时一律编辑，否则会选中一个根本没画出来的 tab）。
- **⑥ 右键菜单的关闭类动作「以右键的那个标签为锚点」，且一次批量关**：容器 `requestCloseTabs(ids)` 收一批 id → 宿主 `chat-view.tsx::handleCloseTabs()` → `tabs.ts::closeTabs()`（内部逐个走 `closeTab` 收敛激活态，**不另写一套邻居规则**）→ **一次落库**。逐个回调会让激活态在中间态里来回跳，还多渲染几次。三条容易被改坏的口径：「关闭已保存」= 只关**非脏**标签（全脏时该项禁用）；「关闭右侧 / 关闭其他」按标签栏顺序算，**最后一个标签上「关闭右侧标签页」必须禁用**；批量里夹着未保存草稿只问**一次**（逐个问会弹一串对话框），取消就一个都不关。文件类动作复用 `ContextMenu/menus.ts::fileMenuItems(..., { withOpen: false })`（面板头已有「在系统程序中打开」，别给同名第二入口）。**「刷新」也在这个菜单里、不在面板头**（头部只留图标按钮）：它要重新读盘 + 有草稿先确认，逻辑都住在 `workspace-file` 里，所以面板挂载时通过 `onReloadReady` 把动作登记给容器（`reloadRegistrarOf` 按标签 id 缓存稳定引用，标签关掉时随脏回调一起清），菜单项只做转发 —— 别把 `load()` 再搬到容器里写第二份。
- **⑦ 标签栏溢出靠横向滚动，滚轮得自己接**：`.side-panel-tab` 是 `flex: none`（标签不压缩、文件名不被挤成省略号），标签一多就横向溢出；`overflow-y: hidden` 让纵向滚轮打上去什么也不发生，所以 `tab-scroll.ts::wheelScrollLeft()` 把 `deltaY` 换算成 `scrollLeft`（`deltaMode` 1/2 按行高 / 可视宽折算）。**监听必须自己挂非 passive 的原生 `wheel`**：React 的 `onWheel` 在 root 上带 `passive: true`，里面 `preventDefault()` 不生效。拦不拦只看「该不该滚」：不溢出、或 `deltaX` 占优（触控板横滑 / Shift+滚轮）返回 `null` 放行（浏览器自己会滚，再加一遍就是双倍速）；溢出时**滚到两端也照样拦**，否则滚轮会穿透去滚聊天区。滚动条颜色走令牌 `--scrollbar-thumb`（亮 #ccc / 暗 #585b70），**且不能写 `scrollbar-width`** —— 一给标准属性 Chromium 就忽略 `::-webkit-scrollbar-*`，暗色主题下冒出浅色滚动条。
- **⑧ 拖标签换顺序只能用鼠标事件，不能用 HTML5 拖拽**：`dragDropEnabled: true`（拖文件进输入框要真实路径，§11.8）时页面收不到 HTML5 `drag` / `drop`，`draggable` 根本不触发。所以 `side-panel/index.tsx::startTabDrag()` 自己挂 `mousedown → document.mousemove/mouseup`，超 `DRAG_THRESHOLD`（4px）才算拖动（否则还是一次点击）。四条容易改坏的口径：① 落点只看**开始拖那一刻**其他标签的中线快照（用实时 DOM 中线的话，标签一重排中线跟着跑，指针停在两格之间会来回跳）；② 容器拖动中只做**就地预览**（`moveTab` 本地重排），松手才 `onMoveTab(id, toIndex)` 上报宿主一次，两边同一个下标口径（宿主 `chat-view.tsx::handleMoveTab()` → `tabs.ts::moveTab()`）；③ 松手那次 `click` 是拖动的尾巴，`suppressClickRef` 吃掉它（同一标签 + 400ms 时钟窗口，不是永久标志 —— 否则指针不在标签上松手会吞掉下一次点击），不能顺手把标签激活；④ **被拖的那一份是挂在 `body` 上的浮层（克隆标签本体），横纵都跟指针**：`.side-panel-tabs` 是 `overflow-x: auto` + `overflow-y: hidden`（横向滚动条的另一半），在栏里写 `translateY` 一定会被裁掉 —— 拖去左侧栏的会话行时标签只能横着滑、上下不动，看着像「它还赖在标签栏里」。所以越阈值时 `raiseGhost()` 克隆一份（`.side-panel-tab.is-tab-ghost`，`position: fixed` + `pointer-events: none` + `inert`，`z-index` 与工作区的 `tree-drag-ghost` 同一档 3000），本体 `visibility: hidden` 留在栏里当**落点空格**（用 `visibility` 而不是 `display`：格子必须还在，否则邻居会挤过来、重排预览就废了）。浮层位移直接写 `style.transform`（不走 state —— 每帧 setState 会把整个面板含编辑器一起重渲染，拖起来一跳一跳）；因为浮层是 fixed 的，与标签栏重排无关，**不再需要「重排后校正位移」那一套**。另一个坑：浮层最宽 270px、会话行也就这么宽，压在某行上时它会遮住「松手就落这一行」的高亮 —— 所以命中会话行时给浮层加 `is-over-session` 淡到 0.4。
  ⚠️ **内容块（`.side-panel-pane`）千万不能跟着标签顺序重排**：`tabs` 一换序，`tabs.map` 就把 pane 的 DOM 挪了位置，React 会把那棵子树的效果**重连**（dev StrictMode 下还会双调用），而 `@monaco-editor/react@4.7` 的 mount-only 清理会 `editor.dispose()` 却不清自己持有的实例，紧接着的一次性 effect 又 `setModel` 到已 dispose 的编辑器上 —— 控制台就是 `InstantiationService has been disposed`（`codeEditorWidget._createView`）+ 视图 rAF 里 `Cannot read properties of undefined (reading 'domNode')`。所以 pane 一律按**打开顺序**渲染（`paneIdsRef` 只看增删不看顺序），内容区另用 `useMemo` 隔开，拖动中干脆不重渲染里面的 Monaco。
  **同一个拖动还能把标签交给另一个会话**（拖到左侧栏的会话项上）：落点登记在 `sidebar/session-drop.ts`（侧栏登记 `.session-list` 容器，行上 `data-session-row`），**按会话行的 rect 命中**而不是 `elementFromPoint`（被拖的那一份永远压在指针下，后者只会命中它自己）；提示只标**落点那一个**，靠 `classList` 直接写 DOM（`.tab-drop-target`；拖动中每帧 setState 会把侧栏刷成幻灯片）。⚠️ **不要给所有会话行描虚线圈**（`.tab-drag-active` 那套已删）：满屏框反而看不清到底会落哪。四条口径：① **指针离开标签栏就不再算换顺序**（落点退回原位，否则往左拖时所有中线都在右边 → 松手把标签踢到下标 0）；拖出标签栏又不在会话行上 = 取消；② **自己的会话行不算落点**（也不高亮）；③ 松手走 `onTransferTab(id, sessionId)` → 宿主 `chat-view.tsx::handleTransferTabToSession()` → `sessions.ts::transferTab()`：标签对象**整体照搬**（id 是渲染 key，改了就卸载重挂 → 草稿 / 终端屏幕 / 网页历史全没），源桶激活态按 `closeTab` 收敛，目标桶追加 + 激活 + 自动展开；④ 目标桶已有**同内容**标签（`tabs.ts::tabContentKey`，与各 `open*Tab` 去重同一口径，不含会话前缀）时不搬，`reason: 'duplicate'` 由宿主提示一句 —— 一桶里两条同内容标签会让「再打开一次」永远只认得到第一条；⑤ **看不见的会话行一个都不接**（这条最容易写错）：折叠的分组是 `grid-template-rows: 0fr` + 内层 `overflow: hidden` 把内容**裁掉**的，行本身照样有尺寸正确的 rect、坐标还落在后面那段可见内容上（裁切不影响 `getBoundingClientRect`）。所以 `sessionDropHitAt()` 要筛掉 `closest('[inert]')` 的行与 `checkVisibility({ checkOpacity: true, checkVisibilityCSS: true })` 判为不可见的行，否则指针压在展开分组里的可见行上会先撞上前面某个收起分组里**同坐标的隐形行** —— 高亮亮在看不见的行上，标签却进了另一个会话；命中区间还要先与列表可视区求交（滚出视区的那段不算），两行之间的 1px 缝隙按 `ROW_SNAP`（4px）吸附到最近一行。
  **反方向也成立：拖侧栏会话项的徽标 = 把那批标签搬走**（`sidebar/session-badge-drag.ts`）：三块落点 —— 右侧面板的**标签栏**与整个**聊天区**（`registerDropArea` / `dropAreaHitAt`；两块各自亮 `.is-drop-target`）= 搬进**当前**会话（标签栏只有 36px 高，逼用户去命中一条细缝没道理；聊天区的高亮是 `.chat-main.is-drop-target::after` 整块透一层，写 `box-shadow: inset` 会被子元素的背景盖住）；**另一个会话行** = 搬去那个会话（自己的行不算）。松手走 `onTransferSessionTabs(from, toSessionId | null)` → 宿主 `chat-view.tsx::handleTransferSessionTabs()` → `sessions.ts::transferSessionTabs()`（与 `transferTab` 同一套口径，只是**整批**：搬完源桶清空、徽标随之消失；目标桶已有同内容的那几个跳过，部分成功也算搬成，全跳过才提示）。拖徽标复用拖标签那一套：鼠标事件 + 挂在 `body` 上的浮层 `.is-tab-ghost`（标签栏 `overflow-y: hidden`、侧栏分组会裁内容，浮层只有 `position: fixed` 才能一路跟手）；拖完那一下 `click` 用 `badgeDragJustEnded()` 吞掉（否则会顺带把那个会话的面板打开）。
- **⑨ 占满态（`is-full`）往回拖必须还能拖回来**：「拖不动」是两个原因叠出来的，缺一条修都不管用。① **层级**：占满时面板左缘正好压在左侧栏的拖拽条上，`.sidebar-resizer` 是 `z-index: 10` 且 `::after` 把命中区向两侧各撑 3px，而面板手柄只有 `z-index: 5` —— 6px 的手柄整条被盖住，mousedown 落到「拖左侧栏」上（面板宽度纹丝不动，还把布局挤出去）。所以 `.side-panel.is-full .side-panel-resizer` 抬到 20；只在 `is-full` 抬 —— 这时聊天区已被 `display:none` 藏起来，抬层级不会和任何东西打抢，非占满态两者也压根不重叠（中间隔着 ≥ 450px 的聊天区）。② **上屏宽度**：占满态显示的是 `available`（不是 `width` 里记的偏好值），拖动中若还按 `available` 上屏，前 450px（`CHAT_MIN_WIDTH`）面板一动不动，用户会直接长按不出效果。现在 `shownWidth = expanded && !resizing ? available : width`：拖动中一律跟手，松手才铺满 / 收回；`mousedown` 时先把 `width` 同步到眼前这条边（`rect.width`），按下去那一瞬间才不会跳一下。另加 `.side-panel { margin-left: auto }` —— 占满态聊天区是 `display:none`，面板不贴右就会从左铺、往右缩（手柄停在原地，又是一次「拖不动」）。
- **⑩ 拖动期间 iframe 必须不参与命中**：HTML 预览是**独立文档**，指针一进 iframe，`document` 上的 `mousemove` / `mouseup` 就收不到了 —— 向右拖 = 指针进面板，拖动断在半路、松手还停在 `is-resizing`（向左拖进聊天区则没事，所以容易被当成「偶尔失灵」）。`.side-panel.is-resizing iframe { pointer-events: none }` 解决：只在拖动那段窗口内禁掉命中，松手立刻恢复（预览里的链接 / 脚本交互不受影响）。容器里以后再加 iframe（网址访问等）也自动被这条覆盖。
- **⑪ 显隐靠 `is-collapsed`，容器**常驻挂载**：收起 / 展开只是给同一个 `<aside>` 加 / 去一个类（宽度 0 + `overflow: hidden` + 不接指针），宽度过渡把聊天区推开 —— 不能用 `transform` 代替（那只是面板自身平移，聊天区仍会瞬间跳）。不要再回到「没标签就卸载 + 延后 200ms 摘掉」那套（已删 `presence.ts`）：现在面板里装的是**多个会话**的标签内容，卸载一下就把别的会话的草稿与终端屏幕一起抹了。**宽度定在「第一次量到非 0 可用宽度」那一刻**（`widthSettledRef`）：容器从窗口挂载起就在树上，首帧常常量不到（布局没排好），无条件在挂载时算一次会永远停在兜底 560。（宽度过渡里聊天区确实会跟着变宽 / 变窄，但消息列表不会一帧一折行 —— 见 ⑱。）
- **⑫ 收起 / 切会话都不清状态，靠会话分桶 + `parkedTabs`**：右侧栏属于**会话**而不属于窗口 —— `side-panel/sessions.ts` 按会话分桶（新对话页一桶），宿主 `chat-view` 只把**当前那一桶**当 `tabs`、其它桶摊成 `parkedTabs` 交给容器**一直挂着**（`hidden`，不进标签栏）。四条容易改坏：**(a)** 标签 id 要带会话前缀（`<key>\u0000`）—— 文件标签本来是「路径即身份」，同一个文件在两个会话里各开一份就会撞 id（同一份草稿 / 两个 xterm 抢一个伪控制台）；所以 `tabs.ts` 的去重**一律按内容判**（kind + 路径 / 服务 / 终端 id），把 `id` 当不透明渲染 key；前缀**只加一次、之后不再改**（别按「前缀 = 桶 key」写判断 —— 找开始页要用 `sessions.ts::guideTabIdIn` 按 kind 找）；**新对话页那一桶在会话 id 落地时整桶过继**（`sessions.ts::adoptNewBucket`，在 `chat-view` 的 `doSend` 里与 `setValue('currentSessionId', …)` **同一个同步块**调，否则面板先按空桶闪一帧；这一步要是漏了，用户看到的就是「发完第一条消息，好端端的右侧栏直接消失」；标签对象整体照搬、`id` 一个字都不改 —— 它是渲染 key，改了内容块就重挂，草稿 / 撤销栈 / 终端屏幕 / 网页历史一起没，文件面板的 `sessionId` 也由前缀反解、一改就重读盘把草稿洗掉）；**(b)** 容器里所有「活着」的集合（`paneIds`、脏回调表、刷新登记表）都要算上 `parkedTabs`，否则切回去时那张表已经被清掉，圆点与菜单项都没了；**(c)** 上报给宿主的「有未保存草稿」只算本会话（收起 / 切会话不再需要确认，只剩切工作目录那条）；**(d)** 文件面板要用**标签自己的** `sessionId`（`sessions.ts::paneSessionIdOf`）解析工作区 —— 用当前会话的 id 会让挂着的那份去错误的工作区找路径，甚至把草稿当成「外面的文件」重读。**杀终端只走三条**：关标签 / 切工作目录（清本桶）/ 会话被删（`withoutSessions`）与组件卸载 —— 收起与切会话**不再杀**（面板看不见 ≠ 终端该停）。工具栏「右侧栏」按钮在**收起时挂一个标签数徽标**（`.toolbar-badge`，数字 = 当前会话的标签数），否则用户完全看不出里面还有东西；**别的会话**「还开着几个标签」靠侧栏会话项徽标 + 开始页清单（同一个问题，见 ⑲）。**代价要说清**：切走的面板没被卸载，它们的 monaco 模型 / xterm 实例也一直占着内存 —— 这是「不丢草稿与终端屏幕」换来的，不要把「标签内容懒挂载 / 卸载释放」当成优化随手加回来（那就又回到「切会话=清状态」）。
- **⑬ 常驻挂载 ≠ 常驻订阅：盯磁盘 / 目录的只给「正在被看」的那一个**：面板里可能同时挂着十几个标签（本会话其它标签、别的会话的、收起时那一批），每个文件标签各订一个父目录 watcher 的话，一次落盘就是十几次整文件重读 + 十几次 hidden Monaco 的最小编辑。所以容器算一个 `live = 当前激活标签 && !collapsed`，作为 `active` 传给 `workspace-file`（订 `watchWorkspaceFile`）与 `workspace-tree`（订 `use-dir-watch`）。四条口径：**(a)** 不活跃**立刻退订**（`useEffect` 依赖里加 `active`，`false` 时直接 `return`）；**(b)** 回到活跃时**先读一次盘对齐 hash**（`checkDisk` → `readDiskChange`），不等事件 —— 不盯期间 AI / 终端可能改过，不补这一次就是「看到旧内容 + 基线 hash 过期 → 保存时才报冲突」；树同理把正在看着的那几层静默 `loadDir` 一遍（不置 loading、不动展开 / 选中 / 滚动）；**(c)** **挂载那一轮不对齐**（`firstWatchRef` / `firstLiveRef`）：`load()` / `loadDir(rootPath)` 正在读，再读一遍等于把大文件读两次；**(d)** 文件树的树根要用**标签自己的**会话（`paneSessionIdOf` → `WorkspaceTree` 的 `sessionId`），否则别的会话挂着的那棵树会去当前会话的目录里订 watcher。⚠️ 别把这条做成「不活跃就卸载」—— `active=false` 只是不订 watcher，组件仍然挂着（草稿 / 撤销栈 / 滚动位置得留着，那才是 ⑪⑫ 的目的）。
- **⑭ 标签的「选中」不能靠自身底色，得靠薄涂（否则两档主题都在说反话）**：`.side-panel-tab` 原来激活底是 `--bg-primary`、悬停底是 `--hover-bg`，看着很合理，算出来是：亮色 `#fff`/栏底 `#f7f7f8` = **1.07:1**、悬停 `#f0f0f0`/栏底 = **1.06:1**（选中和悬停一样弱，且都低于能看出的阈值）；暗色激活 `#1e1e2e`/栏底 `#181825` = **1.07:1**，悬停 `#313244`/栏底 = **1.40:1** —— **悬停比选中还亮**，于是「划过的像选中、选中的像没选中」。现在两档统一成 theme-agnostic 的薄涂：**悬停 = `color-mix(in srgb, var(--text-primary) 7%, transparent)`**（亮 1.14 / 暗 1.16）、**激活 = `color-mix(in srgb, var(--primary) 20%, transparent)`**（亮 1.35 / 暗 1.26，恒强于悬停）。三条口径：**(a)** 激活底上的文字必须仍是 `--text-primary`（对薄涂底亮 12.1 / 暗 9.7）—— 照抄 `.git-tab` 的 `color: var(--primary)` 在暗色只有 **3.75:1**，12px 小字不达标；**(b)** 别再写「`border-bottom` 涂成 `--bg-primary` + `margin-bottom: -1px`」假装接上内容区：标签栏 40px、标签 26px、`align-items: center`，标签下边缘离栏底线还有 4~5px，那条线与自身底色同色 = 画了等于没画（真要接上得先改几何 `align-items: flex-end`）；**(c)** 这类「合法但界面上错」的配色只能算对比度钉住 —— `side-panel-style-contract.test.ts` 会把两档主题的令牌读出来，算「激活 > 悬停 > 常态」与「激活底上的文字 ≥ 4.5:1」。顺手补的：标签按钮要 `font-family: inherit`（`<button>` 不继承页面字体，UA 是 Arial，拉丁文件名会和旁边不是同一套字形）、标签与两颗栏内按钮都该有 `:focus-visible`。
- **⑮ 一个标签 = 外层 div + 内层 `role="tab"` 按钮 + 平级的关闭按钮**（**不能**写成按钮嵌按钮）：`<button>` 里再放 `<button>` 是非法 HTML（解析器会把外层提前闭合），React 渲染时直接报 “In HTML, <button> cannot be a descendant of <button>. This will cause a hydration error.”。三条口径：**(a)** 外层 div 挂拖动 / 右键 / 「点空白也切过去」的 `onClick`，而 `role="tab"` 与 `aria-selected` 必须归**内层那颗真按钮**（键盘 Tab 到的是它，`:focus-visible` 焦点环也画在它身上 —— 把这两个属性挂到一个不可聚焦的元素上，等于把标签页语义挂空）；**(b)** 关闭按钮的 `onClick` 必须 `stopPropagation()`：外层 div 也开着「点标签就激活」，关一个**没选中**的标签不能反手把它选中；**(c)** `tabRefs` 存的是**外层 div**（`scrollIntoView` 与拖动位移都作用在它身上），类型用 `HTMLElement` 而不是 `HTMLDivElement` / `HTMLButtonElement` —— 换 DOM 标签时别让类型跟着漂（写成具体标签类型，`tsc` 会在下一次改结构时报 TS2741）。守卫：`side-panel.test.tsx`（每个标签一颗 `.side-panel-tab-btn` + `aria-selected` / 点标签上报 / 拖动中不误触发 / 关闭不激活）。

- **⑯ 系统里拖进来的文件：监听只能有一份，落点才分多份**：`dragDropEnabled: true`（§11.8）时页面收不到 HTML5 drag / drop，唯一通道是 Rust `drag_drop` 下发的 `virlen:drag-drop`（带物理像素坐标 + 真实路径）。落点从「只有输入框」变成「输入框 + 右侧栏」之后，**各处自己 `listen` 就会把一次拖放处理两遍**（文件既进附件又开标签），「拖到空白处」的提示也会互相打架。所以监听只挂在宿主（`chat-view.tsx` 的 `useNativeFileDrop()`），输入框与面板只各登记一个「命中范围」（`ui/hooks/useNativeFileDrop.ts` 的 `useNativeDropTarget()`）。四条口径：**(a)** 命中**按坐标算**（`position ÷ devicePixelRatio` 再与 `getBoundingClientRect()` 比），不靠 DOM 事件冒泡 —— 所以提示层必须 `pointer-events: none`（`.side-panel-drop-hint`），一旦它能接指针，拖动期间里面的编辑器 / iframe 就收不到事件；**(b)** rect 宽高为 0 的落点**直接跳过**：收起的右侧栏（`width: 0 !important`）不跳的话，贴边那几个像素会被误判成命中（拖上去既开不出标签，也拿不到提示）；**(c)** 高亮只在**换落点**时回调一次（`over` 每帧都来，逐帧 setState 会把面板刷成幻灯片）；**(d)** 开标签归宿主：容器只上报 `onDropPaths(paths)`，且宿主先问 `stat_path` 把目录 / 已失效路径挑掉（`workspace-file-service.ts::splitDroppedPaths`）—— 否则会变成一个“该路径不是文件”的错误标签。守卫：`src/tests/ui/side-panel-drop.test.tsx`（矩形内命中 / 聊天区不命中 / 拖入提示 / 收起不接 / 宿主没给回调不接 / 卸载后注销）。

- **⑰ 文件标签分「预览位」与「常驻」，而「能顶掉的只有干净的预览位」**：用户点开 / 拖进来的文件是**预览位**（`SidePanelTab.pinned !== true`，标签文字斜体 `.side-panel-tab.is-preview`）—— 下一个打开的文件**顶掉它那一格**（下标不变、标签数量不变，逛文件树不会攒出十几个「路过看一眼」的标签）；`present` 的交付物是**常驻**，谁都不顶它。四条口径：
  **(a)** 升级只有四条路，而且**全部收在 `tabs.ts`**（容器 / 宿主只负责转话，别在别处再写一遍判断）：present 交付（`pinned: true`）、**再次打开已经激活的它**（`openFileTab` 的 `current.id === activeId` = 用户点第二遍「我要留着」）、**双击标签**（`onPinTab` → `pinTab`）、**改动了草稿**（容器在脏上报那一刻 `pinTab`）。常驻之后**永不退回**预览位 —— 那是用户的判断，不该被下一次点击改掉。
  **(b)** 为什么「改动」必须当场升级：顶掉预览位 = 那一格的面板**卸载**（草稿与 Monaco 撤销栈一起没）。预览位永远是干净的，所以顶掉它**不需要任何确认**（`requestCloseTabs` 那套「放弃未保存的修改？」只归关标签用）；只要脏的那一刻没升级，用户的字就会被下一个文件静默吃掉。反过来，「支持编辑」不用另判 —— 只有文本文件会脏，媒体 / PDF / Office / 3D 连草稿都没有。
  **(c)** 一次打开多个（拖进来三个文件 / present 批量交付）只让**第一个**去占预览位，其余追加：`handleOpenFiles` 里把 `activeId` 只传给第一轮（`slotOwner`），否则三个文件会互相顶、最后只剩一个。
  **(d)** 顶位不改变标签数量，`sessions.ts::withBucketTabs` 的「标签变多就展开面板」判不出来 —— `handleOpenFiles` 末尾要显式 `applyBucketOpen(key, true)`，否则面板收起时点文件会「点了没反应」。
  **(e)** 「预览位斜体」不是写一句 `font-style: italic` 就完了 —— **本项目里它完全无效**：界面字体 `AlimamaAgileVF-Thin` 没有 italic 字面，`src/ui/App.css` 的 `:root { font-synthesis: none }` 又把合成斜体关了（试过 `font-synthesis-style: auto` 与 `@font-face { font-style: oblique 0deg 12deg } + font-style: oblique 12deg`，无头 Chrome 截图实测都不出斜体）。这款变量字体自带 `slnt` 轴（0→12），`font-variation-settings: 'slnt' 12` 能出**真斜体**，但**只改拉丁字形** —— 中文文件名（`说明.md`）一个像素都不斜，预览位就在那些标签上失形。同理，所以容器用的是**几何倾斜** `.side-panel-tab.is-preview .side-panel-tab-name { display: inline-block; transform: skewX(-10deg); transform-origin: left center }`：与字体 / 回退 / 脚本无关，中英文都盖到。⚠️ 顺便记住一条**全局事实**：`font-synthesis: none` + 无斜体字面的组合让整个应用原本的 `font-style: italic` 都是摆设。现在分两条路修：
  - **行内文字 / 语义标签**（markdown 的 `*斜体*`、`<em>`、`<i>`、引用块）：这三条**一起**写才真的斜 —— `font-style: italic`（选真字面）+ `font-synthesis-style: auto`（只在这一层把合成开回来，中文走系统回退字体靠它斜）+ `font-variation-settings: 'slnt' 12`（这款变量字体的真斜体字形）。口径只写在 `src/ui/App.css` 的 `em, i, cite` 一处，markdown 的 `.md-blockquote` 抄同一份（行内元素**不能**用 `skewX`：`transform` 对非替换行内盒不生效，加 `inline-block` 又会让长段斜体跨不了行）；
  - **短标签**（右侧栏预览位）：用 `skewX`（理由同上：标签里可能是中文文件名，而 `slnt` 只管拉丁字形）。
  同类「合法 CSS 但零效果」的坑必须钉成断言：`side-panel-style-contract.test.ts` 钉面板那条，`italic-contract.test.ts` 钉全局 `em/i/cite` 与 markdown 引用块的三条。

- **⑱ 宽度过渡期间把消息列表的宽度钉在终值，否则「面板一边滑、内容一边抖」**：面板宽度是从 0 ↔ 实宽过渡的，`.chat-main` 是同一行的 `flex: 1` —— 不钉的话消息列表在那 200ms 里一帧换一个宽度，每一行都得重新折行：`use-virtual-list` 的逐行 `ResizeObserver` 一轮接一轮地报实测高度，虚拟滚动再按行高差补偿 `scrollTop`（`scroll-hold`）。观感就是一边滑一边抖，长会话（上千行）还明显掉帧。做法：`side-panel/chat-freeze.ts::freezeChatWidth()` 在**过渡开始的那一帧**（容器的 `useLayoutEffect`：DOM 已改、还没画）把终值写进 `.chat-main` 上的 `--chat-freeze-width`，`message-list.scss` 里 `.chat-messages-container { width: var(--chat-freeze-width, auto) }` 消费它 —— 面板滑过去只是盖住 / 让出空白，内容一动不动，整段过渡**只折行一次**。四条口径：**(a)** 终值只用**当前真实布局**算（`容器右边界 − 面板终宽 − 聊天区左缘`，三个量在过渡里都不动），别拿取整过的 `available` state 去减 —— 差半像素摘锁时就会二次折行；**(b)** 拖动中**不钉**（宽度本来就跟手，`.is-resizing` 也关掉了过渡）；**进**占满态不钉（聊天区 `display:none`）—— 但**退**占满态（全屏 → 半屏）必须钉，而且那一帧聊天区宽度正好是 0（面板还占着整块可用宽度、`flex: 1` 只能拿 0），所以「有没有布局」只能看**高度**：宽度 0 是合法的过渡起点，只有矩形全 0（`display:none`）才算没布局；**(c)** 锁只活在过渡窗口内（`PANEL_WIDTH_MOTION_MS` + 余量后自己摘；卸载与下一次过渡在同一帧里摘-重设），**别把它做成常驻宽度**；**(d)** 变量名是 `chat-freeze.ts`（唯一写入点）与 `message-list.scss`（唯一读取点）的**成对契约**，写错不报错、只是钉不住。守卫：`src/tests/ui/side-panel-chat-freeze.test.ts`（终值算式 / **退出占满态那一帧宽度是 0 也要钉** / `display:none` 不写 / 窗口期后自动摘 / 摘锁幂等）+ `side-panel.test.tsx`（展开·收起·占满态不钉·**退出全屏重新钉回半屏终值**·卸载摘掉）+ `side-panel-style-contract.test.ts`（变量名 / 读取点 / 摘锁时长 = 样式表的 width 过渡时长）。
- **⑲ 「哪一桶还开着标签栏」必须外显（侧栏徽标 + 开始页直达清单）**：标签属于会话、面板一次只显示一桶，别的桶的标签只是 `hidden` 挂着 —— 切走之后用户**没有任何线索**知道哪个会话还开着标签栏（工具栏徽标只统计当前会话）。两处外显，同一份数据（`sessions.ts::panelTabSummaries` / `parkedBucketsOf`）：
  **(a) 侧栏会话项徽标**（`sidebar/index.tsx::renderSession`）：`count > 0 && !isCurrent` 才显示 —— 当前会话的标签数在工具栏那颗按钮上，两处说同一件事就是噪音；数字口径 = `tabs.length`（**开始页也算一格**，与工具栏徽标一致，否则「侧栏说 2、工具栏说 3」会被当成 bug）；`open === false` → `is-collapsed` 只留描边（标签挂着但没摊开）。徽标是真 `<button>`（行本身是 div，不存在「按钮嵌按钮」），`onClick` 必须 `stopPropagation` 再上报 —— 它的动作是「切过去 + 展开」，不能让整行那个「选中会话」顺带跑一遍（两个副作用谁先谁后说不清）。
  **(b) 折叠分组头汇总**：分组折起来之后组里那些徽标全看不见，组头补一枚组内总数；它是纯计数（`pointer-events: none`），点它仍然是折叠 / 展开分组 —— 不替用户挑一个会话。
  **(c) 开始页「其他对话的标签页」清单**（`guide.tsx`）：按会话分组列 `parkedBucketsOf` 的结果，一行一个标签，点了由宿主 `handleOpenSessionPanel(sessionId, tabId)` 一次落地。三条口径：标签名**只有一份实现**（`side-panel/tab-title.ts::tabDisplayName`，标签栏 / tooltip / 本清单共用 —— 写两遍必然分叉，同一个终端在一处叫「PowerShell 7」、另一处叫 `terminal:3`）；`guide` 不算内容不进清单（别的会话里它只是一张门厅）；会话标题由**宿主**补（容器拿不到会话 store），宿主把标题拼成 `panelTitleSig` 当 memo 依赖 —— 只用 `panelBuckets` 会让清单停在旧标题上，每次现造数组又会把容器 `body` 的 memo 打穿（里面的 Monaco 跟着重渲染）。
  **(d) 切桶顺序**：`handleOpenSessionPanel` 先改桶（`withBucketActive` / `withBucketOpen`）再切过去，**同一个同步块**；分两次渲染会先闪一帧「展开了但还是旧标签 / 还收着」。切过去分两条路：真会话走 `handleSelectSession`；**新对话页那一桶（`NEW_PANEL_KEY`）没有 sessionId**，`handleSelectSession` 查不到会话会直接返回（点下去像没反应）—— 它走「新建对话」同一条路（`chatState.set({ currentSessionId: null, error: null })`），**且必须把 `handledSessionRef` 归零**，否则外部入口（托盘唤起）再打开刚离开的那个会话时，兜底 effect 会以为已经处理过而跳过数据准备 —— 就是 §11.13 那条「跳过去但消息列表是空的」。
  **(e) 代价说清**：徽标不区分标签类型（不列文件名），它是「那儿有东西」的指示器、不是第二个标签栏；要找具体标签就点徽标回去，或从开始页清单直达。守卫：`side-panel-sessions.test.ts`（摘要口径 / 跳过新对话页与空桶 / `withBucketActive` 原引用三条）+ `sidebar-panel-badge.test.ts`（只给非当前会话 / 两档样式 / `stopPropagation` / 分组汇总 / 接线与文案）+ `side-panel-guide.test.tsx`（清单分组 · 计数 · 点击上报 · 没东西时不画）。

**11.55 右侧栏的「开始页」与「工作区文件」标签：四条不能踩的** —— 参考 deepseek-harness 的引导页形态：面板空出来时不是空白，而是三扇门（工作区文件 / 新建终端 / 浏览器），点一扇门把它原地换成对应的页面。落地时有三条容易改坏：
- **① 开始页是「门厅」，不是常驻标签**：点胶囊必须走 `side-panel/tabs.ts::replacePageTab(tabs, 'files', GUIDE_TAB_ID)` —— 目标页**接管开始页那一格**、开始页同时消失。写成 `openPageTab`（追加）就会留下一个「开始」标签，用户会以为那里能回首页；而目标页已经开着时只激活它、顺手把开始页关掉。
- **② 文件树的样式现在挂在根上**（`sidebar/style.scss` 里 `.workspace-tree` / `.sidebar-search` / `.sidebar-empty` 三条带 `@at-root`）：同一棵树既在左侧栏也在右侧面板（`onPickGuide` → `files` 标签，`variant="panel"` 只改「单击即开」这一条），样式再挂回 `.chat-sidebar` 下面，右侧那份就变成没有行高、没有 hover 的裸文字。⚠️ 往这三块里加规则时不要再依赖 `.chat-sidebar` 祖先。
- **③ 键帽与键盘匹配必须同源**：`ui/shortcuts/commands.ts` 是唯一一份（`keys` 展示 + `code`/`modifiers` 匹配），开始页的 `<kbd>` 由它渲染，`chat-view` 的 `keydown` 也由它判定。⚠️ 工作区文件用的是 `Ctrl+Shift+E`，**不是**参考实现的 `Ctrl+P` —— 后者的本项目语义是「消息检索」；两条键都在输入框 / `.xterm` 里让路（`isTypingTarget`），否则会在用户敲命令时劫持 readline 的 `Ctrl+E`。守卫：`tests/ui/side-panel-guide.test.tsx`（三扇门顺序 / 终端已接入·浏览器仍禁用 + 「即将支持」 / 无工作区禁用（连 ▾ 一起） / 胶囊上报 = 整行直开且不弹菜单 / 没有「按钮嵌按钮」 / `+`·`»` / 树的 `variant=panel`）+ `tests/ui/terminal-shells.test.tsx` / `tests/ui/side-panel-tabs.test.ts`（`openPageTab` / `replacePageTab` 的单例与原地替换口径）。
- **④ 「新建终端」整行 = 直开，挑类型是文案后面那颗 ▾**：点整行走 `onPick('terminal')`（**不带** shell → 宿主 `resolveShellChoice` 用「上次用的 → 后端默认」，与 `Ctrl + \`` 同一条路），只有 ▾ 弹 `shellMenuItems` 的菜单（`anchorElement` 传 ▾ 自己，再点一次才关得掉）。没有 `loadShells` 就**不画 ▾**（不摆一颗点了没东西的控件）；探测不到类型或一个可用的都没有时，▾ 也直接开默认那种（不弹一片全灰的菜单）。⚠️ 结构上**绝不能**把 ▾ 写成「`button` 里的 `button`」：HTML 不允许（解析器会把外层提前闭合），React 还会报 “<button> cannot be a descendant of <button>”。所以一扇门是「同一格网格叠两层」—— 铺满整行的 `-hit` 真按钮负责主操作（可 disabled / 键盘可达），`-body` 是看得见的内容层且 `pointer-events: none`，只有 ▾ 用 `pointer-events: auto` 开回来。改样式时别给 `-body` 加回 `pointer-events`（会挡住整行命中区），也别把 hover / 焦点环摄到 `-body` 上（`:hover` 留容器、`:focus-visible` 在 `-hit` 上，否则键盘用户看不到焦点）。

**11.56 用户终端（右侧面板「新建终端」）：八条容易踩的** —— 用户自己的 shell 与后台服务、`execute_command` 共用同一个 ConPTY 底座，但**语义完全不同**（谁在敲、过不过沙盒、关掉之后还剩什么）：
- **① 默认脱壳是产品决策，不跟沙盒设置走**：用户亲手敲的 `npm install` / `git commit` 必须能跑（与 VS Code 内置终端一致），所以 `user_shell/spawn.rs` **不**调 `prepare_sandbox_session`，头部**不**挂「沙盒已关闭」徽标：`SandboxBadge` 只画真在沙盒里的两种（`write_isolation` / `readonly`），`no_sandbox*` 五档一律不画 —— 脱壳是常态（设置里关掉沙盒 / 命中忽略规则 / AI 申请脱壳 / 用户终端），常驻一枚红标只会变成噪声，真要人当场注意的脱壳在**审批弹窗**那一步已经拦过。⚠️ 反过来也别以为这条放宽了「AI 执行必须过沙盒」—— 那条线在 `execute` / `service` 里，两条链互不影响。
- **② 关标签 = 关终端（但**收起面板 / 切会话不是**）**：`chat-view::killTerminalsIn` / `withoutSessions` 覆盖四条路 —— 标签栏 × 与右键批量关、切工作目录（清本会话那一桶）、会话被删（丢桶时把标签交回来）、组件卸载（所有桶）；收起面板与切会话**一条都不杀**（面板看不见 ≠ 终端该停，草稿与屏幕都还留着，切回去要继续能敲）。Rust 的 `cmd_terminal_kill` 幂等，且摘条目时会放下带 `KILL_ON_JOB_CLOSE` 的 Job 兜底。漏掉任何一条闭合路径就是「`npm run dev` 占着端口没人知道」；反过来多杀一条就是「我只是切了个会话，跑了一半的构建没了」。
- **③ 首帧必须上报尺寸**：`info === null`（轮询还没回来）时**不能**拦尺寸上报 —— 与 §11.54 服务终端同一个坑（拦下会回 `true`，而「成功不重试 + 同尺寸不重复上报」让这次上报永远补不回来，伪控制台停在创建时的默认尺寸）。
- **④ 终端 id 只给界面**：`user_shell` **不是**原生工具，`NATIVE_TOOL_NAMES` 不该加它（会连带改工具契约与工具数）；模型没有入口去操作用户的终端，键击内容也绝不下发（`write_terminal` 只回布尔）。
- **⑤ 复用 `ServicePty` / `LogBuffer`，不要改名重写或复制一份**：关停顺序（**进程退出 → 落终态 → `ClosePseudoConsole`**）、尺寸去重、`reset` 续接协议这三件事在服务与用户终端必须逐字一致。非 Windows 没有 ConPTY：`spawn_shell` 返回明确错误（**不**退化成管道 shell，否则 `vim` / `top` 全不工作，用户会以为终端坏了）。
- **⑥ 终端标签的标题就是终端类型名（PowerShell / cmd / PowerShell 7 / Git Bash），不编序号**：重名无所谓（靠 tooltip 里的工作目录区分），用户要的是「这是什么终端」而不是「第几个」。所以 `tabs.ts` 的终端标签**没有 `index` 字段**（旧实现那个「已用最大值 + 1」的撞号口径已随字段一起删干净）—— 别再往标签上编「终端 1 / 2」，也别把序号加回字段里：它只会在关闭 / 重排时跟着别人的生死漂流。
- **⑦ 输出必须“推”，不要靠轮询**：ConPTY 把用户键入**回显进输出流**，而轮询的间隔就是**回显延迟** —— 350ms 的轮询意味着「敲一下等一帧」，快打时几个字符攒成一批跳出来（2026-10-13 收到的手感反馈就是这个）。现在 core 的 `user_shell::spawn_pusher` 按帧推（`TerminalOutputHost` 由 GUI 注入，发 `terminal:output`；与 `service::notice` 同一套「trait + 全局出口」写法，core 零 `tauri::`）：每帧带 `[from, next)` **绝对偏移**、16ms 前沿节流合并突发（首帧不等）、**终态（`running` 翻转）也走推送**；前端 `use-user-console` 只在 `from` 与本地游标严丝合缝时直接追，对不上就回头 `readUserTerminal(from=cursor)` 补一帧 —— **丢帧不丢内容**。⚠️ 三条容易踩：**(a)** 起始偏移必须在 `spawn_pusher` 的**同步部分**取（放进 `async` 块里取，任务首次被调度之前到达的输出会被当成「客户端自己读的那段」永远不推 —— 单测里稳定复现）；**(b)** 补帧**绝不要按字符下标切字符串**（Rust 偏移是 `char` 数、JS 的 `slice` 是 UTF-16 码元，emoji 会错位），要么整帧用，要么「读的过程中游标被推送推进了」就整帧弃掉重读；**(c)** 慢轮询（1s）必须留 —— `exitCode` / `interactive` / `headDropped` /「被摘出注册表」没有事件，它同时是丢帧的兜底。参考：dsh 的 `api/terminal-controller`（输出是带 `sequence` 的帧流，前端 `xterm.write` 写完回调里才 ack 做背压；输入逐次立刻发、不 debounce）。
守卫：`cargo test -p virlen-core user_shell`（会话隔离 / 容量 / cwd 只认存在的绝对路径 / 四种 shell 的探测与解析 / 未知 id 报错 / 推送任务的偏移与终态 / Windows 端到端真 ConPTY 写读关，含 `cmd` 与装了就测的 `pwsh` / `git bash`）+ `src/tests/ui/user-terminal.test.tsx`（头部没有沙盒徽标 / 推送直落 / 断档补读 / 重复帧忽略 / `running=false` 立即禁输入 / 结束后退出码 / 头部 ✕ 交给宿主；「增量续接」「被摘表后停轮询」「切走不发请求」三条要真实等 1~2s，已随测试提速删除）+ `src/tests/ui/sandbox-badge.test.tsx`（写隔离 / 只读才画徽标，`no_sandbox*` 五档一律不画）+ `src/tests/ui/terminal-shells.test.tsx`（展示名 / 排序与首选 / 显式 > 上次 > 后端 / 菜单项灰显与「上次使用」标注 / 开始页整行直开·▾ 弹菜单·再点一次关掉 / 只有终端有 ▾ / 没有 `loadShells` 就不画 ▾）+ `side-panel-*.test.ts(x)`（终端标签的 id·标题（shell 类型名，不编序号）·原地替换、开始页把类型列表接到菜单上）。

**11.57 浏览器标签（右侧面板「浏览器」）：十五条容易踩的** —— 网页是面板里唯一「内容不属于本地」的一格，而**它不在 iframe 里**：`X-Frame-Options: SAMEORIGIN`（virlen.cn 就是）对 iframe 是硬限制，浏览器只给一片空白、拒绝原因只进控制台；dsh 的桌面端（`ElectronWebviewPresentation.ts` 的 `<webview>`）与这里的**原生子 WebView** 是同一类东西 —— 独立浏览上下文，服务器不知道它被摆在哪一格，那套响应头不适用。落地在 `src-tauri/src/browser_view.rs` + `infrastructure/browser/browser-view.ts` + `browser/use-native-view.ts`：
- **① `Window::add_child` 只能从异步命令里调**：它内部 `run_on_main_thread` 之后**阻塞等主线程**，写成同步 `#[tauri::command] fn` 就跑在主线程上 —— 直接死锁（界面卡住，没有任何报错）。该 API 还挂在 `tauri = { features = ["unstable"] }` 下，关掉 feature 会整个消失。同名 label 必须先 `close()` 旧的：React StrictMode 的「挂载 → 卸载 → 再挂载」与热重载都会撞上 `WebviewLabelAlreadyExists`。
- **② 位置 / 尺寸必须逐帧同步，且不可见只能 hide 不能 close**：子 WebView 是**原生窗口**，浮在 HTML 之上，不随 DOM 布局走。`use-native-view.ts` 用一条 rAF 循环读挂载点的 `getBoundingClientRect()`，与上一帧比对（容差 0.5px）后才发命令；面板 200ms 的宽度过渡、拖分隔条、窗口缩放都靠这条跟上。⚠️ 两条容易漏：**(a)** 切标签 / 收起面板时 rect 全是 0，此时只能 `hide` —— `close` 会丢滚动位置、表单、登录，而 `is-collapsed` 的过渡里还得跟着宽度一起缩；**(b)** **拖分隔条时必须先把视图藏起来**（读祖先 `.is-resizing`）：原生子窗口会吃掉 `document` 上的 `mousemove` / `mouseup`，指针一进它的矩形拖动就断在半路 —— `.side-panel.is-resizing iframe { pointer-events: none }` 只管 DOM 里的 iframe，对原生窗口无效。
- **③ 位置 / 尺寸 / 显隐走同一条命令**：`browser_view_apply(label, x, y, w, h, visible)`。拆成三条并发执行的 async 命令会乱序 —— 从隐藏恢复时「先显示、后定位」，用户看到视图在旧位置闪一下。Rust 侧一条命令里先 `set_position` → `set_size` → `show`，顺序由代码保证而不是由调度器保证。
- **④ 导航是命令，地址靠事件回传，历史只有 Chromium 那一份**：只有地址栏回车才 `navigate`（同一地址再来一次算刷新，走 `reload` 命令）；页面自己跳走 / 服务端重定向只更新地址栏（`browser:navigate` 的 `started` / `finished` / `location`）—— **绝不因此补一次导航**，那是「回退又跳回去」的根因之一（地址那一路刚把页面导到目标页，原生后退又把它退回去，落在过渡页上再跳一次，见 ⑮）。面板不存历史条目，后退 / 前进只发原生命令。⚠️ 进度条要有 15s 兜底：DNS 失败 / 证书错时可能永远等不到 `finished`，不能一直转。
- **⑤ 外部网页碰不到本应用的命令，但这件事要有据**：Tauri 2 对**非本地来源**发起的 IPC 一律要求显式 `remote` capability（`tauri/src/webview/mod.rs::on_message` 的 `!is_local` 分支），本应用的 capabilities 里没有 `remote` —— 网页即便拿到 `__TAURI_INTERNALS__` 也调不动任何一条命令。**再加一道 `browser_view.rs::REMOTE_LOCKDOWN`（`initialization_script_for_all_frames`）**：`invoke` 被拒**不是静默的** —— 在网页里点一个 `<a target="_blank">`（百度首页的图标导航就是）就会留一条 `Uncaught (in promise) shell.open not allowed on window "main", webview "browser-view-1", URL: https://www.baidu.com/`，而那条命令本来就不通，脏的只是控制台。⚠️ **「删掉入口」行不通**（试过）：`__TAURI_INTERNALS__` 是 `Object.defineProperty(window, …)` 装的（没有 `configurable`）、`window.ipc` 是 `Object.freeze` 的，页面级 `delete` / 重定义都是静默失败。所以从两个可控的面收：**(a)** `<a target="_blank">` 在 DOM 层 `preventDefault` + `location.href` 就地导航 —— WebView2 根本不发「新窗口请求」（语义与 `on_new_window` 的 `Deny` + 同视图导航一致，但走普通导航，地址栏 / 历史照常回传）；**(b)** 把 `ipc-protocol.js` 那条 `fetch("http://ipc.localhost/…")` **掐成永不 settle**（不能改成报错：报错会让它回退到 `window.ipc.postMessage` 那条真的能通的通道）。另外三条自己钉：导航白名单只有 `http` / `https` / `about:blank`（`file:` / `tauri:` / 未知协议一律拒），带用户名密码的地址拒（会被写进标签标题与历史），`on_new_window` 返回 `Deny` 并在同一个视图里导航（面板只有一个视图，凭空弹窗用户不知道它去哪了）。⚠️ 事件要用主 webview 的 `emit`，**不能 `app.emit` 广播** —— 那等于把浏览记录回灌给网页自己。
- **⑥ 建不起来必须能说出来**：不在桌面应用里（浏览器调试）或命令报错时，`use-native-view` 的 `error` 落到一张说明卡（「网页视图启动失败」+ 原因 + 「在系统浏览器中打开」）。⚠️ 失败后要置 `failed`，否则 rAF 每帧都会重试一次 `open`（日志刷屏、界面抖动）；**改地址时重置**，让下一次导航重新获得机会。首帧也别给白屏：视图建起来之前挂载点里放「正在加载…」，原生视图会盖住它。
- **⑦ 标签标题用页面自己的 `document.title`，不是主机名**：`on_document_title_changed`（Tauri builder）+ Windows 的 `DocumentTitleChanged` 原生事件把标题回传，`tabs.ts::updateBrowserTitle` 写进 `SidePanelTab.title`，标签栏取 `tab.title || urlLabel(tab.url)` —— 拿不到标题时退回主机名，绝不能渲染一个空标签。⚠️ 两条：**(a)** 标题与地址是两件事（SPA 换标题时 `url` 可能没变），别写成一个「一起更新」的函数；**(b)** `trim()` 后为空的标题不写入 —— 页面加载前期 `document.title` 是空串，写进去标签会瞬间变空。标题很长时靠 `.side-panel-tab { max-width: 270px }` + `.side-panel-tab-name` 的单行省略，别在 JS 里截断（中英文宽度差太多）。
- **⑧ 下载必须拦下并说一声，不能交给 WebView2 的默认行为**：`on_download` 不注册时，点一下下载链接文件就**直接写进系统下载目录** —— 面板里没有浏览器那种下载栏，用户只看到「点了没反应」，磁盘上却多了个来路不明的文件。这里的口径是**一律不落盘**：`WebviewBuilder::on_download` 收到 `DownloadEvent::Requested` 就 `return false`（wry 会 `args.SetCancel(true)`），同时把文件名（`destination` 的末段，拿不到再退 URL 最后一段）以 `phase = "download"` 发回主 webview；`BrowserPane` 在顶部出一条 `.browser-notice`：「网页尝试下载文件，已阻止」+ 文件名 + 「在系统浏览器中打开」（优先下载链接本身，`blob:` / `data:` 退回当前页）+ 关闭。⚠️ 三条：**(a)** 提示**不自动消失**（静默正是要修掉的那个问题），只有用户点关闭才收；**(b)** 这条提示会占一行高度，内容区被推下去 —— 原生视图靠逐帧 rAF 自己跟上，别给它写死高度；**(c)** 参考实现 dsh 桌面端是 `will-download` → `preventDefault()`、**没有任何提示**，别照抄 —— 那正是「点了没反应」的来源。
- **⑨ 传给原生视图的坐标是「逻辑像素」，必须把 `getBoundingClientRect()` 的 CSS 像素乘上界面缩放**：主 webview 的 `setZoom` 是**页面缩放**（1 CSS px 放大成 `zoom` 个 DIP），而子视图是**另一个 WebView2 控制器**，不会跟着缩放；Tauri 的 `LogicalPosition` / `LogicalSize` 只含**窗口 DPI**（`scale_factor`），不含 page zoom。所以 `zoom = 1.25` 时 `rect` 要乘 1.25 再传，不乘就是「视图比占位小一圈、整体往左上收」（缩放越大差得越远，2 倍时只剩 1/4 面积）。⚠️ 三条：**(a)** 倍率要取「**已落地**」的那个值 —— `ui/hooks/applied-zoom.ts`，由 `applyWebviewZoom` 在 `await setZoom(...)` 成功后才写；别读设置里的期望值（`settingsState.zoomFactor` 先变、页面布局后变，照它算会先撑大一两帧再收回）；**(b)** 倍率变化不需要单独的重同步信号 —— 乘完之后 bounds 自然变，逐帧比对会自己发；**(c)** 不要改成在 Rust 乘：`tauri::Webview` 没有 zoom 的 getter（只有 `set_zoom`），那个倍率只能在主 webview 里拿到。
- **⑩ 被 DOM 浮层盖住时必须自己躲（原生子窗口不吃 `z-index`）**：设置页 / `Modal` / 抽屉 / 右键菜单都是 portal 到 body 的 DOM 浮层，而原生子 WebView 是**窗口的子窗口**，绘制层级永远高于 HTML —— `z-index: 1300` 的 Modal 也压不住它（症状：打开设置页，网页仍浮在最上面，而它还会**吃掉鼠标**：点设置页的按钮，事件落到网页上）。所以 `use-native-view.ts` 的逐帧同步里多一道判定：拿占位**中心点**做 `document.elementFromPoint`，命中的元素跑出 `.browser-viewport` 就让视图 `hide`（`coveredByOverlay`），遮罩掀掉后下一帧自动 `show`。⚠️ 三条：**(a)** 用命中测试而不是维护「浮层清单」（`.settings-overlay` / `.modal-overlay` / `.summary-drawer` / `.context-menu` / 全局提示…）—— 列清单一定漏，新加浮层也不会有人记得回来改；**(b)** 取**中心点**是刻意的近似：全屏遮罩型（设置页 `.settings-overlay` 是 `fixed inset: 0`、Modal 的 `.modal-overlay` 同理）必然命中，局部浮层只在真压住主要区域时才让位（遮一个小角就藏会变成闪烁）；**(c)** 隐藏时要把占位里的「正在加载…」一起收掉（hook 多回一个 `covered`），否则半透明遮罩下会透出一行字。**别想用 `set_position` 把视图挪开或缩小来「避让」** —— 那会改网页自己的视口尺寸（触发页面 resize / 重排），下一帧还得挪回来。

- **⑫ 命中测试没必要逐帧做（2026-10-14）**：⑩ 那道 `elementFromPoint` 每帧一次，等于每秒 60 次强制命中测试，而遮挡结论只在浮层开合时变。现在按 **100ms 降频** + `MutationObserver` 盯 `document.body` 的直接子节点（浮层都是 portal 到 body 的）：开 / 关浮层那一刻立刻补一拍重测，其余时间不再白算。⚠️ 别退回逐帧，也别只留定时降频 —— 后者会让开设置页那一瞬「网页仍盖在上面」（最坏 100ms）。

- **⑪ 存活策略：看不见就不跑帧，闲置就释放（2026-10-13）**：原来 rAF 无条件接力，每个网页标签（含切到别的会话后 `parked` 的那些）每秒 60 次白量一次布局；现在**看得见才逐帧**，整体不可见就停掉 rAF，由 `ResizeObserver` + `visibilitychange` 唤醒（没有 RO 的环境如 jsdom 低频 250ms 兜底）。外加两条按设置执行的释放策略（`browser/view-policy.ts`，设置项 `browserSleepAfterSec` 默认 20 秒 / `browserMaxViews` 默认 10 个，0 = 关）：**切走超时清掉** + **超出上限时淘汰最久没看的隐藏视图**。⚠️ 四条：**(a)** 只销毁不导航 —— `wantUrl` 留着，可见时重建并重载当前地址（页面内状态会丢，设置页文案已写明）；**(b)** 在用的那一页绝不被自己关掉（淘汰只挑 `inUse === false`）；**(c)** 「被浮层盖住」不等于「切走」：前者 `inUse=false` 但 `parked=false`，不计闲置时间（否则开着设置页一会儿就把所有网页清掉了）；**(d)** 重建后原生历史栈已空，hook 回 `slept` 计数，`BrowserPane` 据此把后退 / 前进历史收敛成当前页 —— 不做这一步，两个按钮会指向已经不存在的页面，点了没反应。

**⑬ 消息里的链接开在右侧栏的网页标签（2026-10-26）**：Markdown 正文里的 `http(s)` 链接被点后不再交给 webview 开新窗口，而是开面板里的网页标签（判定 / 拦截在 `message/markdown-link.ts`，**唯一出口** `services/browser-open-service.ts`，入口由 `chat-view.tsx` 的 `handleOpenBrowser(true, url)` 注入 —— 与 `present-service` 同一个「宿主登记、渲染层调用」套路，因为标签状态只有宿主有）。四条口径：**(a)** 只接管**绝对的 http(s)**（先按字面前缀筛，再过 `browser/url.ts::normalizeAddress`）—— `#锚点` / `./a.ts` / `mailto:` / `file:` / `//example.com` 一律保持 `<a target="_blank">` 原行为，把 `./a.ts` 丢给地址校验会被「无协议补 https」当成主机名，开出一个空白外网标签；**(b)** 修饰键（Ctrl / Cmd / Shift / Alt）与非左键**不接管**（那是用户在说「我不在这儿开」）；**(c)** 宿主没登记时（不在聊天页 / 用例）**不许** `preventDefault` —— 吞了默认行为就变成「点了没反应」；**(d)** 地址先规范化再交出去（地址栏 / 标签标题 / 原生历史共用同一个字符串）。面板收着、当前会话没有标签都不影响（落桶即展开 `withBucketTabs`），开始页开着就接管那一格。守卫：`tests/ui/markdown-link-browser.test.tsx`（改道口径 / 凭据地址拒绝 / 修饰键与非左键 / 注销不顶掉新实例 / 渲染出来的 `<a>` 真的接上并吃掉默认行为）。

**⑭ 交付物也可以是一个网址（`present` 的 `links`，2026-10-26）** —— 模型把一个页面交给人看（文档站 / 已发布的预览页），以前只能把网址写进正文让用户自己点。现在 `present` 的 `path` / `paths` **也收 `http(s)://…`**：它不进 `files`（那条路要 `resolve_safe_path` + 扩展名预览判定，网址进去只会得到「file does not exist」），而是进 **`uiData.links`**（`{ url, name }`，`name` = 主机，标签文字用它），前端开成面板的**网页标签**。五条口径：**(a)** 以「含 `://`」分叉，不靠正则猜 —— Windows 盘符（`C:\x`）没有 `://`，归文件；**(b)** Rust 侧只做三条最小校验（**协议白名单 http(s)** / **主机非空** / **不带 `user:pass@`**），故意不引 `url` crate：规范化在地址栏那一侧（`browser/url.ts::normalizeAddress`），两处都改一遍必分叉；**(c)** `files` + `links` **合计**上限 10（面板是标签页，开一堆没人看），同一个网址重复声明只收一次；**(d)** 「一个都没收下」才报错 —— 只交网址是**成功**，旧口径「没文件 = 失败」会让模型以为没交成；**(e)** ⚠️ 铁律 1：Rust `present.rs` 与 TS 回退执行器 `infrastructure/tools/file/present.ts` 的**正文文案与 `uiData` 形状必须逐字一致**（`files[].path` / `links[].url` / `skipped[].reason`），工具定义（`definitions.json` **三平台各一份**）也要同步说清楚「也收网址」。守卫：`cargo test -p virlen-core present`（网址 + 文件混交 / 重复网址去重 / 带凭据与 `ftp://` 被跳过 / 只交网址算成功 / 没主机报错）+ `tests/infrastructure/present.test.ts`（TS 镜像同一套）+ `tests/services/present-event.test.ts`（`presentedOf` 两项 / 只有网址也摊开）+ `tests/ui/present-message.test.tsx`（网址条显示主机 + 点击走 `browser-open-service`）。

- **⑮ 重定向 / 过渡页不许面板自己「清历史」：后退 / 前进归 WebView2（2026-10-26，二次修正）** —— 现象：点开一个链接、后面跟一串 302 / 过渡页，按「后退」又把过渡页加载一遍、又跳回去，面板历史长成 `[A, L1, L2, T]`。**第一版在面板里维护合成历史，用两个启发式把重定向「折成一条」，两个都在猜，而猜错就是删掉用户真去过的页面**：`HOP_GAP_MS`（两跳间隔 < 1.2s 就当同一串跳转）会把「快站点点两个链接」并成一条；「落回出发页就 `historyDrop` 删条目」会把「登录后跳回原页 / 站点回首页」这类合法回跳判成中转页。现在的口径照 dsh 桌面端（`ElectronWebViewImpl`：`element.goBack()` + `element.canGoBack()`）—— **历史只有一份，就是 Chromium 自己的**：**(a)** 面板不存历史条目，`browser/url.ts` 只剩地址校验（`normalizeAddress` / `urlLabel`），`historyGo` / `historyReplace` / `historyDrop` **全部删掉** —— 没有能删数据的逻辑；**(b)** 后退 / 前进只发原生命令：`browser_view_history` 在 Windows 走 `CoreWebView2::GoBack` / `GoForward`（经 `with_webview` 派到主线程；命令是 async、不在主线程上跑，所以不死锁），其他平台退回 `history.back()` / `history.forward()`。302 在提交那一刻由 Chromium **替换**掉进行中的那一条，`GoBack` 因此直接回到出发页 —— 折叠本来就不需要前端做；**(c)** 按钮可用性只认原生：`SourceChanged` 顺手读 `CanGoBack` / `CanGoForward`，跟 `location` 事件一起回传（`canBack` / `canForward`）；拿不到（非 Windows / 还没提交）时按「有地址就放行」兜底 —— 栈底 / 栈顶点一下顶多什么都不发生，绝不会导错地方；**(d)** ⚠️ 导航是命令不是受控值：`use-native-view` 对外只给 `navigate` / `reload` / `goBack` / `goForward`，地址只用于显示，「地址变 → `navigate`」那条路必须不存在（它就是第二个根因）；**(e)** 兜底只收进度条：15s 没等到 `finished` 就停进度条，不动地址、不发命令（`currentBrowserViewUrl` 只剩核对价值，面板不调）。守卫：`tests/ui/browser-pane.test.tsx`（后退 / 前进只发原生命令且不 `navigate` / 302 与多跳过渡页期间面板**零命令** / 快速连点两条导航都如实上报 / 按钮状态只认事件 / 15s 兜底）。

守卫：`src/tests/ui/browser-pane.test.tsx`（四类地址拒绝 / 本机补 http / **后退与前进只发原生命令、绝不补一次 `navigate`** / **302 与多跳过渡页期间面板零命令** / **快速连点两条真导航都如实上报（不再按间隔折叠）** / **按钮可用性只认 `canBack` / `canForward`，平台不上报时才按「有地址就放行」兜底** / 刷新走 `reload` / 页面自跳写回真实地址 / SPA `location` 只改地址 / **15s 加载兜底只停进度条** / 逐帧 apply 与「rect 为 0 只隐藏不销毁」/ **rect 乘界面缩放后才传（CSS px → DIP）** / **被 DOM 浮层盖住时躲开（只 hide 不销毁）** / 建不起来给说明卡 / 下载拦下并提示）。

**11.58 终端四种 shell（cmd / powershell / pwsh / git bash）：装没装必须先探测，而且不能只查 PATH** —— `user_shell/shells.rs` 是唯一一份探测（`detect_all` / `resolve` / `parse`），Tauri 命令 `cmd_terminal_shells` → 前端 `listUserTerminalShells` 先拿列表，**未安装的灰显并标「未安装」**（悬停还能看到「查过哪些目录」）—— 而不是让用户点了才收到一句「启动 pwsh 失败：系统找不到指定的文件」。三条容易踩：
- **① Git for Windows 只把 `<git>\cmd` 加进 PATH**（`git` 能用、`bash` 找不到）：所以除了常见安装目录，还要**由 PATH 上的 `git.exe` 反推** `<git>\bin\bash.exe`。本机就是 `C:\config\Git` 这种定制安装 —— 只按 PATH 找 `bash.exe` 会在装了 Git 的机器上判「未安装」。
- **② `C:\Windows\System32\bash.exe` 是 WSL 的入口，不是 Git Bash**：PATH 搜索必须排除（`is_wsl_bash`，连 WindowsApps 里的别名一起排除），否则「Git Bash」起来的是 WSL，prompt / 路径 / 工具链全不是用户预期的，还会以为这个终端坏了。
- **③ id 与展示名必须分家**：core 只回稳定 id（`powershell` / `cmd` / `pwsh` / `gitbash`），展示名在 `ui/pages/chat/components/terminal/shells.tsx::shellLabel`（产品名 / 命令名不翻译，`cmd` 就叫 cmd，没有 `en-US` 条目；中文即 key 的机制自然兜底）。把中文展示名写进 Rust，英文界面就翻不出来；反过来把路径存进设置也会在换机器后失效 —— 记忆存的是 **id**（`settings.terminalShell`）。

另三条口径：**`Ctrl + \`` 不弹菜单**（显式选的 > 上次记的 > 后端默认，`resolveShellChoice`），开始页的「新建终端」**整行点下去也直开**，只有标题后面那颗 ▾ 才弹类型菜单（选完就记住；见 §11.55 ④）；`-NoProfile` 一律**不带**（终端是用户自己的环境，别名 / prompt 要生效）；`TERM` 也不手动注入 —— msys2 的运行时自己会给 `xterm-256color`，硬塞反而可能盖掉用户的设置。

⚠️ 单测注意：**msys2 在受限令牌下起不来**（`couldn't create signal pipe (Win32 error 5)`）。在沙盒化的终端里跑 `cargo test -p virlen-core` 时，git bash 那个 e2e 会先用 `std::process` 探一下、探不动就打印 `[skip]` 跳过；`sandbox::windows::tests` 那组 ACL 用例同样会在沙盒里假失败 —— 都是环境限制，真实令牌下 958 条全绿。

**11.59 前端渲染期的四处白烧（2026-10-14）** —— 性能体检时找出来的四条，都是「没有行为收益、只花 CPU」：

**11.60 运行中命令的输出：只解析增量，否则是 O(n²)（2026-10-14）** —— `execute/common.ts::processTerminalOutput` 是逐字符状态机（`\r` 覆盖 / ANSI / 清屏 / Tab / 退格）。运行中的命令每 50ms 通知一次 UI（`output-store.ts::NOTIFY_INTERVAL_MS`），而 `output` 是**累积串**：每次都从头解析，一轮几 MB 的输出就能把渲染进程主线程卡住几秒。现在 `TerminalOutputParser` 保留解析状态（行缓冲 / 光标行列），`feed(累积串)` 只解析上次之后新增的那段，并且：**(a)** 幂等 —— 重复喂同一长度直接返回（React StrictMode 会重复渲染）；**(b)** **末尾半截的转义序列留到下一块** —— `\x1b[` 被切在两个 chunk 之间是常态，当正文吐出去就是乱码；**(c)** 输出变短（换了一条流）就重置。`processTerminalOutput` 退化成一次性包装（`new Parser().feed(raw)`），单次结果仍与 Rust `common.rs::process_terminal_output` 逐条对齐。⚠️ 两条：**尾部空行只在 `text()` 输出时跳过，不能从 buffer 里裁掉** —— `\x1b[B` 的边界按 `buffer.length` 夹，裁了就和全量解析不一致；**解析器按 `toolCallId` 一份**，换命令必须重建（旧状态跨命令复用会把两段输出叠在一起）。守卫：`tests/infrastructure/terminal-output.test.ts`（1~5 字符任意切分的结果都等于一次性解析 / 转义序列跨块 / OSC 跨块 / 重复喂幂等 / 变短重置 / 尾部空行不影响光标定位）。

**11.61 消息列表「最小化再切回来位置变了」：scrollTop 被夹掉且不会自愈（2026-10-25）** —— 聊天区是独立滚动容器（`.chat-messages-container`），它的 `scrollTop` 在两种情况下会被浏览器**夹掉且永不恢复**（无头 Chromium 实测）：**(a)** 内容高度塌到 0（`.vm-list` 的 height 由虚拟库的实测总高决定）；**(b)** 视口高度一度高过内容。窗口最小化 / 恢复、右侧面板占满把聊天区 `display:none` 藏起来都会撞上这两条。四条口径：**(a)** 行高**量到 0 一律不收**（`use-virtual-list::measureRowHeight` 是库 `measureElement` 的包装）：0 只表示「还没布局」，写进缓存会把 sizer 的总高一起塌掉；**(b)** 意图 = 「贴底 / 停在第 N 行行内 M 像素」（`scroll-restore.ts::anchorAt` / `nextIntent`）—— **不能只记像素偏移**：行重测 / 估算改值会让同一偏移落到别的内容上；几何不可信的两拍（视口 0、内容比视口矮）**保留上一次意图**，否则「用户本来贴底」正好在塌陷那一拍被抹掉；**(c)** 判据不是「scrollTop 是不是 0」：中段同样会被夹成**非 0** 的小偏移，按锚点算出的目标差超过容差就写（`restoreTargetOf`），容差内不动，免得与虚拟库自己的补偿打架；**(d)** 复位是一个**窗口**（`use-scroll-controller::restoreLostPosition`：连续几帧把位置拉回锚点、连续 3 帧不动才收）：恢复动画逐帧改高度、浏览器写完后又补写自己的偏移、行重测也在后面几帧 —— 只纠一次就会停在半路。窗口期间**冻结意图**（否则被夹出来的位置会被记成用户意图），用户一动滚轮 / 触摸 / 按键立即收手。⚠️ 触发点三个（容器高度 RO / `visibilitychange` / 窗口 focus），`display:none` 本身不丢偏移（Chromium 会存下来再补回），丢的是「内容 / 视口几何被改坏」那一刻；切会话 / 首开的贴底仍归 `settleToBottom` 独占。守卫：`tests/ui/message-list-scroll-restore.test.tsx`（0 高度不入缓存 / 意图在塌陷与视口 0 时不被覆盖 / 锚点优先于像素偏移；「贴底与被夹成 0 或非 0 都回到原处」「复位窗口内被再次推走仍拉回」三条要真实等 260ms，已随测试提速删除，取回见 `git log`）。

**11.63 自绘标题栏的按钮是「面板外面」：点最大化会把浮层连同弹窗一起收掉（用户报回 → 已修，2026-10-26）** —— 现象：git 差异弹窗开着时点窗口右上角的「最大化」（或双击标题栏），弹窗直接消失。根因链：`WindowLayout` 的最小化 / 最大化 / 关闭是**自绘的 DOM 按钮**（`.control` + `onClick` → `toggleMaximize`），所以那一下是真实的 `mousedown`；而所有弹窗遮罩都从 `--window-top-bar-height` **下方**开始（故意的：压住标题栏会让拖窗口 / 点窗口按钮在弹窗开着时失效）—— 于是这下的 target 既不在遮罩里、也不在 `.git-entry` 里 → 入口的「点浮层外关闭」判成「点了外面」→ `setOpen(false)` → `GitPanel` 卸载 → portal 到 body 的弹窗跟着没了（面板也一起消失）。口径：**只要面板自己的遮罩还在（`.git-diff-backdrop`（差异 / 日志 / 提交图 / 贮藏共用）/ 全局 `.modal-overlay`），这一下就不算「点在外面」** —— 按 `document.querySelector` 判**存在**，不按 target 判（按 target 只能拦住「点进遮罩里」，拦不住「点标题栏」）；此时除标题栏外没有可点的地方，忽略它没有副作用，遮罩撤掉后点外面照旧收面板。守卫 `tests/ui/git-entry-overlay-guard.test.tsx`（git 遮罩 / 全局 Modal / 无遮罩 三情形；回退成按 target 判时前两条立即变红）。其它入口将来开遮罩照这份抄。

**11.64 3D 预览里 GLB 与同款 FBX 亮度对不上：两家材质模型不同（2026-10-26）** —— 先被报「glb 比 fbx 暗」，按 `metallicFactor` 缺省 1.0 改完又反过来「fbx 比 glb 暗」，说明**不能靠一个常数猜作者意图**。三个常见猜测仍然先排掉：**(a)** 色彩空间 —— `model-scene.ts` 早设了 `outputColorSpace = SRGBColorSpace`（r152 之后本来就是默认值），`ColorManagement` 也开着，贴图色域由 `GLTFLoader` / `FBXLoader` 各自标好（前者按规范线性、后者 `colorSpaceToWorking(..., SRGBColorSpace)`）；**(b)** 后期处理 —— 预览没有 `EffectComposer`，不存在「帧缓冲线性的直接上屏」，也就不需要 `OutputPass`；**(c)** 顶点色 —— glTF 的 `COLOR_0` 本来就按线性存储、加载器直接当线性用，把 sRGB 值写进去只会**更亮**，方向相反。真正的两处不对称都在 `model-loaders.ts`：

**① 着色模型**：`MeshPhongMaterial` / `MeshLambertMaterial` 只有 `RE_Direct` 与 `RE_IndirectDiffuse`（见 `lights_phong_pars_fragment` / `lights_lambert_pars_fragment`），**没有 `RE_IndirectSpecular`**；`envmap_fragment` 的旧式混合又只对 `ENVMAP_TYPE_CUBE` 生效，而预览的环境是 PMREM（`CUBE_UV`）—— 所以 FBX 拿不到任何 IBL 高光，GLB（Standard）漫反射与高光都有：这套以环境光为主的布光下 FBX 结构性偏暗。`normalizeMaterials()` 在 FBX / DAE / 3DS / WRL / OBJ / 3MF / AMF 解析后把 Phong·Lambert 换成 `MeshStandardMaterial`（颜色 / 自发光 / 透明度 / 正反面 / 顶点色 / 各类贴图照搬，`specular` 与 `specularMap` 没有等价物不搬），同一份源材质只换一次以保持共享、换完释放原件。后两种（3MF / AMF）是 2026-10 补的：`ThreeMFLoader` / `AMFLoader` 只造 `MeshPhongMaterial`，漏掉它们就等于「3MF 比同款 GLB 暗一档」。换材质时顺手把**颜色贴图**（`map` / `emissiveMap`）标成 `SRGBColorSpace`：`FBXLoader` / `VRMLLoader` / `MTLLoader` 自己会标，`ColladaLoader` / `TDSLoader` / `ThreeMFLoader` 一个字都不标（保持 `NoColorSpace` → 采样不做 sRGB→线性 → 整张贴图发白）。法线 / 粗糙度 / AO 是**数据**，必须留线性，不能一起标。

**④ 数值口径（`E:\code\3d场景\racecar` 一对实测定位到的真凶）**：Blender 的 FBX 导出器把 **线性**颜色直接写进 `Diffuse` / `Emissive`（数值与 glTF `baseColorFactor` / `emissiveFactor` 逐位相等），而 `FBXLoader` 一律当 sRGB 解 —— **双重解码**：车身漆 0.34 → 0.0946、轮胎 0.017 → 0.0013（暗 13 倍），这就是「FBX 更暗」的真正来源。另两项同样可按换算精确还原：`ShininessExponent = 100·(1-roughness)²`（实测 0.2→64、0.1→81、0.88→1.44 全中），`ReflectionFactor`（`material.reflectivity`）**就是 Principled 的 Metallic**（13 个材质与 glTF `metallicFactor` 逐位相等）。实现：`detectBlenderFbx()` 只扫头部 4KB 的 `Creator`（`Blender (stable FBX IO) - …`），命中后用 `linearToSrgb` 把颜色编码回去、`blenderShininessToRoughness` 取反函数、`metalnessOf` 取 `reflectivity`；实测三项在 racecar 上全部对齐（最大误差 2e-11）。⚠️ 这套只对 Blender 启：Maya / Max 写的 `Diffuse` 是 sRGB，照搬反而会过亮；非 Blender 仍用通用 GGX 反算（`sqrt(2/(s+2))`）且 `metalness: 0`。`ReflectionFactor == Metallic` 是 Blender 4.2+ 稳定 FBX IO 的口径（本文件 addon 版本 5.15.0）；若旧版导出器把它恒写 1，恰好会表现为「整体过金属」，到时按 `Creator` 里的 addon 版本再收窄。

**② 贴图**：`WebGLTextures.setTexture2D` 只在 `texture.version > 0` 时 `uploadTexture`，而加载失败 / `new Texture()` 占位件的 version 恒为 0 —— 采样到未定义内容，`map` 把材质乘成黑的（FBX 里写的是相对路径，面板只有一个文件的字节，读不到是常态）。且贴图是**异步**的：`parse` 返回时每个 `TextureLoader` 的纹理都还没有 `image`，不能在 parse 之后立刻判死。改法 `watchTextures()`：包装 `LoadingManager.itemStart/itemEnd` 计数，一批结束（成功或失败）后 `dropUnloadedTextures()` 只摘「确定坏」的槽并 `needsUpdate`，再 `onLateChange()` 让场景补画一帧 —— 顺带修掉「FBX 贴图不拖一下就不出现」（渲染循环静止后不会自己重绘）。**2026-10 补上的另一半：相对路径现在真能加载到了。** 用户报「helicopter_textured.fbx 没有贴图」，根因是 `FBXLoader` 把 `RelativeFilename` 用 `split('\\').pop()` **只留文件名**、再相对页面基址去取（webview 的基址是应用页面），必然 404。`model-textures.ts` 在 `parse` 之前把模型字节里的贴图路径扫出来（二进制 FBX 的字符串后面紧跟着下一个节点名，所以只认「扩展名之前那段字节」），按模型目录解析（引用里的 `..` 词法展开 → 逐段折掉导出机的绝对路径 → 全落空时按文件名在目录树里找），读成 blob URL 交给 `setURLModifier`；`tga` / `dds` 浏览器解不了，另注册 `TGALoader` / `DDSLoader`（否则 `FBXLoader` 发现 `getHandler('.tga')` 为空会整张跳过）。于是「`texture.version` 恒为 0」只发生在**磁盘上真的没有那张图**时，模型信息里的「贴图 1 / 2」就是它 —— **一张都没找到时显示「0 / N」而不是整行消失**（2026-10 补：`loadModelTextures` 原先在 `found === 0` 时返回 `null`，用户看到的只有一片纯色，连「为什么」都没有；现在只要扫到引用就返回统计，`urlFor` 一个 URL 都不换）。这些静默失败现在都**上屏**了：工具栏末尾的日志图标（徽标 = 警告 + 错误条数）打开「异常日志」弹窗，条目由 `model-diagnostics.ts` 统一收口（标题 / 去重 / 上限 40，口径见 02-subsystems ⑥）。

**③ 金属度那条收窄**：真金属的 `metallicFactor: 1` 恰好等于规范缺省值、导出端会省掉，但它一定写了 `roughnessFactor`；所以 `fixUndeclaredMetalness()` 现在只在 **`metallicFactor` / `roughnessFactor` / `metallicRoughnessTexture` 三者都没写**时才按非金属处理（第一版只看 `metallicFactor`，会把真金属改成非金属、模型反而变亮）。「按网格 → primitive 查定义（primitive 可能没写 `material`，three 给的是 `metalness: 1` 的白色 DefaultMaterial）/ 关联缺失不动 / 改 uniform 不重编译」三条口径不变。

守卫：`src/tests/ui/workspace-file-model-loaders.test.ts` / `workspace-file-model-textures.test.ts`。**仍可能对不上的**：贴图文件真的缺失（模型信息里的「贴图 1 / 2」直接标出来，只能退化成纯色）、作者显式声明了 `metallicFactor` 或挂了金属度贴图（那是意图，预览不该改）、GLB 独有而 FBX 表达不了的扩展（`KHR_materials_clearcoat` / `KHR_materials_specular` —— racecar 的车漆 clearcoat 0.65、玻璃 1.0 在 FBX 里没有对应槽位）、`doubleSided` 在 FBX 里落在 `Culling` 上而 `FBXLoader` 不映射（GLB 全为 true，FBX 是 FrontSide）。

**11.65 3D 预览的「环境」不能放组件 state：面板标签是同时挂着的（2026-10-27）** —— 用户要求「预览多个文件用同一个环境值，并存储到 localStorage」。原先 `presetId` 是 `ModelView` 的 `useState`，看着很自然（一个下拉管一个模型），但右侧面板的标签**同时挂着**（`side-panel` 的 `parkedTabs` 一直不卸载；常驻标签也只切显隐）—— 同时开两个模型 = 两个实例，各自一份 state 就会「改 A 的 B 不动」，用户只能理解成「这个文件不支持某档环境」。现在真相在 `model-environment.ts`：模块级 store + `useSyncExternalStore` 订阅（不上 MobX：需求只有「一个字符串 + 通知」），localStorage 键 `virlen-model-preset` 里**只存 id**（存整份预设会把过期颜色一直带下去），存过旧值 / 手改存储时退回 `DEFAULT_MODEL_PRESET_ID`，读 / 写抛错一律吞（隐私模式 / 配额满最多是「下次打开忘了选哪档」）。两个坑：**(a)** `applyPreset` 只能在**一个** effect 里应用（`[presetId, sceneReady]`）—— 建场景时若顺手也调一次，`sceneReady` 一翻这个 effect 会再调，渐变档每次都要重跑一遍 `pmrem.fromEquirectangular`（白建一张环境贴图，切换时肉眼可见一顿）；**(b)** `setModelPresetId` 值没变时**不通知**，否则点同一个选项会白重渲染 + 重建一次环境贴图。其余开关（线框 / 网格 / 坐标轴 / 自动旋转 / 模型灯光）仍是每个预览各自一份 —— 它们描述「我此刻想怎么看这个模型」，与跨文件要一致的观感基准不是一回事；真要一起统一，加进同一个 store 即可。守卫：`tests/ui/model-environment.test.ts`（默认档 / 旧值退回 / 读写抛错 / 只存合法 id）+ `tests/ui/model-view-loading.test.tsx`（初始值来自存储、一处改档后两个实例的选中值与两个场景都跟着变）。

**11.66 源代码管理面板：「分支浮层比面板高」会把面板撑出滚动条（用户报回 → 已修，2026-10-27）** —— 现象：面板内容不长时点开分支浮层，**面板自己**冒出滚动条（浮层底部的分支得先滚面板才看得到），滚一下浮层还跟着面板一起走。根因：两块浮层（`.git-branch-menu` / `.git-merge-menu`，`position: absolute; top: 74px`，最高 320px，与面板共用 `.git-branch-menu, .git-merge-menu` 那组规则）是 `.git-popover` 的**绝对定位子元素**，而气泡本体被 §11.62 的「压 `max-height` + 自己滚」夹成了滚动容器 —— 只要包含块在滚动容器里，绝对定位子元素的越界部分就算**滚动溢出**，于是「浮层比气泡高」= 气泡多一条滚动条，`scrollTop` 一动浮层就整体位移。⚠️ **不能反着修**：把浮层夹进气泡（`max-height: calc(100% - 74px)`）在空仓库 / 内容很少时只剩几十像素（气泡高度是内容撑出来的，只有一百多），浮层就没法用；`min(320px, …)` 也只是两害取其轻。正确做法是**让气泡本体彻底不滚**：`.git-popover` 显式 `overflow: visible`（它一旦被内联样式带上 `overflow-y` 就复发），高度上限与自滚全部交给新的滚动体 `.git-panel-scroll` —— `GitPanel` 把正文收进 `panelBody` 元素、包在它里面，两块浮层留在它**外面**（仍是气泡的直接子元素，`top: 74px` 的包含块没变）；内边距 `10px 12px 12px` 从气泡搬到滚动体身上（气泡的 padding box 边就是边框内沿，内边距搬走**不影响**浮层的 `top: 74px` / `right: 12px` 锚点，滚动条也仍在内容外侧 12px）。`popoverFit.ts` 因此把返回值拆成两份：`frameStyle`（只有横向位移，给气泡本体）与 `bodyStyle`（高度上限 + 自滚，给滚动体）—— 单层气泡（任务清单 `.todo-popover`）把两份摊在同一个元素上，源代码管理只把 `bodyStyle` 交给 `GitPanel`。⚠️ 别把浮层改成 `position: fixed` / portal 去绕：它们是贴着面板头部展开的（`top: 74px` 就是为了对齐那个位置），改成视口定位就得把锚点矩形、点外部关闭、再点一次切换那套全部重写；窗口最矮 1000×600（`tauri.conf.json`），浮层顶边 ≈ 标题栏 + 工具栏 + 8 + 74，320px 高仍在窗口内，所以没再给浮层做视口夹紧。守卫：`tests/ui/popover-fit.test.tsx`（拆分的 hook 行为 + 两个入口的接线——位移归气泡、上限归滚动体）+ `tests/ui/git-panel.test.tsx`（分支浮层挂在 `.git-panel-scroll` 外面、且是气泡的直接子元素；`bodyStyle` 落在滚动体上）+ `tests/ui/git-panel-style-contract.test.ts`（`.git-popover` 必须 `overflow: visible` 且不带 `max-height`；`.git-panel-scroll` 接管内边距与圆角）。

**11.67 会话列表的分组折叠 / 展开要过渡：`height: auto` 不能过渡，走 `grid-template-rows: 1fr ↔ 0fr`（2026-10-27）** —— 分组头原本是「折叠就不渲染」（`{!isCollapsed && …}`），于是那一折一展是硬切。四条口径：**(a)** 内容必须**常驻**：卸掉就没有内容高度，没有高度就没有起点（顺带保住「展示全部」的展开态与组内滚动位置 —— 一收起就忘掉会让人以为分组重排了）；**(b)** 高度未知时唯一稳的过渡是**外层网格收行轨**：`.session-group-body { display: grid; grid-template-rows: 1fr; transition: grid-template-rows 0.25s ease }`，收起态加 `.is-collapsed` 收到 `0fr`；内层 `.session-group-items` 必须 **`min-height: 0` + `overflow: hidden`** —— 网格项默认 `min-height: auto`，少这一条 `0fr` 收不到 0（表现是「点了折叠，行没了但高度还在」）；`overflow` 只加内层、**不要**加外层（外层一旦成滚动容器，外边距 / 溢出行为跟着变，§11.66 就是同一个坑的另一种写法）。⚠️ 别再拿 `max-height` 猜上限：猜小了裁内容、猜大了动画前快后慢（视觉上就是「先猛一收再慢慢挤」）。**(c)** 高度之外还要给**透明度**：只收高度的话行是被上下「削掉」的（文字会被裁一半），所以内层 `opacity: 1 / 0` + `transition: opacity 0.25s ease`，与行轨**同时长**（两者错拍会先看见一条被压扁的行再消失）。**(d)** 正因为内容「挂着但看不见」，收起态必须 `inert={isCollapsed}`（React 19 直接支持布尔 `inert`）：否则 Tab 键会走进看不见的会话行、`show-all-btn` 还能被键盘点到、读屏也会把整组念一遍。降级由 `App.css` 的全局 `prefers-reduced-motion` 统一处理（本项目所有 transition 都在那一条里降到 0.01ms），不必为本处单写一份。**(e) 图标与折叠箭头共用一格**：分组头左侧那 14px 平时画类型图标、`hover` 时换成折叠箭头（`sidebar/index.tsx` 的 `.group-slot`）—— 两枚平级 + `gap: 6px` 就是 34px，合并后只占 14px。三条容易改错：叠放只能靠**同一网格格**（`> * { grid-area: 1 / 1 }`）+ 各自的 `opacity`，**不能用 `display` 切换**（那会把过渡整段跳过，变成硬闪）；`.group-toggle` 的基规则要把 `transform` 与 `opacity` **两个时长都写上**（只留 `transform 0.2s ease` 会把透明度过渡覆盖掉）；`archived` 的降调必须加在**那一格**上（`.group-slot { opacity: .55 }`）—— 原来写在 `.group-icon, .group-toggle` 上的那条会被更具体的叠放规则整条盖掉，表现是「归档分组跟别的一样亮」。⚠️ **展开与收起分两套**：**展开**的分组常显箭头（`is-expanded` 类，由 `isCollapsed ? '' : ' is-expanded'` 驱动，为它另加一份 state 就是两处真相）；**收起**的分组回落到类型图标，只在 `hover` 时换箭头。理由是两种状态下该说的话不一样：展开时下方摊着会话行，那 14px 是「点这里收起」的把手；收起时方向已经没有可读信息（下面没行），更该说的是「这是什么组」。两套规则的声明必须一致（同一组 `opacity: 0 / 1`），别一边改数值。守卫：`tests/ui/sidebar-group-collapse.test.ts`（内容常驻 · 收起不条件渲染 / `inert` / `1fr ↔ 0fr` 与 250ms 过渡都在 / 内层 `min-height: 0` + 裁切 / 透明度 1↔0 且与高度同时长 / 不许回退成 `max-height`）+ `tests/ui/sidebar-group-slot.test.ts`（两枚在同一槽位 / 同格叠放 / `hover` 用 `opacity` 换脸而非 `display` / 折叠旋转仍在且两个时长都写着 / 归档降调在槽位而不是子元素上）。

**11.68 3D 预览的「网格列表 / 选中模式」：显隐改 `visible`、高亮用独立对象、点选要区分拖视角（2026-10-28）** —— 用户要求「加一种选中模式 + 面板列出网格，能逐网格隐藏 / 显示、能复制名称、能单独显示看那一块的统计」。十七条口径：**(a) 列表只取一次**（`scene.listMeshes()`），之后显隐在本地按**纯函数**改（`model-meshes.ts`，没变化就返回原数组 = 不重渲染），只把**差异**下发给场景 —— 一个 500 网格的模型「单独显示」要翻 499 行，逐行都调 `setMeshVisible` 等于刷 499 次渲染请求。**(b) 显隐只改 `object.visible`，选中高亮用独立 `BoxHelper`**（配 `depthTest: false` + `renderOrder` 才穿墙可见）；选中后**其余网格退成半透明**（`DIM_OPACITY = 0.25` + `depthWrite: false`，不关深度写入则十几个透明网格互相挡成一团），靠替身材质实现、**不能改原件** —— glTF 大量共享材质，改一处连带一片。⚠️ 线框与半透明**共用一条通路**（`applyMaterials`，每次状态变化整批重建）：各写一套就会把对方的替身盖掉，而且换回去时拿到的是对面的替身，**原件（连同贴图）从此没人释放**。**(c) 点选必须与拖视角区分**：`pointerdown` → `pointerup` 位移 < 4px 才算点击（`OrbitControls` 仍按全部网格算**：出过一次真问题（2026-10-28，用户报「单独显示后区域跑到原点，再显示全部整个模型就穿过地板」）——「单独显示」当时调的是 `frameObject`，它会为取景**重新缩放 / 平移整棵树**；那是「加载后把模型摆进画面」的一次性动作，再摆一次位置就漂了，而且回不去（`homeTransform` 记的是**加载时**的原始变换）。现在：挑网格只调 `focusVisible()`（只改相机位置与目标点，**一律不碰 `object.scale / position`**），方向沿用当前视角；`frameObject` 的包围盒也改成**与可见性无关**（`subjectBox(object)`，要只看可见就显式传 `visibleOnly`）—— 否则「重置视图」等于「按当前可见部分重排一遍」，藏几个网格后点两下就沉下去了；「显示全部」顺带把镜头收回全模型（`resetView`，全可见时结果与加载时一字不差）。**(e) 面板只能 `position: absolute` 盖在舞台上**：做成舞台的 flex 兄弟节点，面板一开画布立刻矮一大截（与 §11.54 `display: none` 同一条精神的另一面）。**(f) 选中详情压右下角**（列表在左上、信息卡在右上），**不挂在列表下面** —— 列表几百行时，选中靠后那一行就永远看不到详情；它也不受面板开关约束（画布点选后直接可见）。**(g) 图标必须用线条**：`App.css` 有全局 `svg { fill: var(--icon-color) }`，而 CSS **盖得住** svg 上的 `fill="none"` 呈现属性（属性权重是 0）—— 只在组件里写属性的话睁眼图标会被填成一个黑饼，必须在 `.wfp-mesh-eye svg` 里显式 `fill: none; stroke: currentColor`。**(h) 地面要沉下去 `0.001`**（`GROUND_Y`）：地面、网格线与模型底面**都在 y = 0**，深度值一模一样 → 网格线在模型底下闪、底面一条条缝（z-fighting）；只沉地面、**网格线留在 0**
